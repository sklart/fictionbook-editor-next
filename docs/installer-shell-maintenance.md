# Обслуживание системной интеграции установщика

BAT `packaging/nsis/Installer/MakeInstaller.bat` и `create-release.ps1` вызывают
`tools/build/build-installer.ps1`. Скрипт принимает готовые Core и Integration,
проверяет staging, объединяет их и вычисляет SHA-256 для трёх файлов именно
из полученного NSIS input. Пустые файлы и отсутствующие stages прерывают сборку.
NSIS дополнительно сверяет хеши с payload и отклоняет пустые, не шестнадцатеричные,
неполные и не соответствующие содержимому значения.

Для короткой пересборки из подготовленных stages:

```powershell
.\tools\build\build-installer.ps1 -CoreDirectory out\stage\Core -IntegrationDirectory out\stage\Integration
```

BAT принимает те же параметры, включая `-OutputDirectory` и `-OutputFile`.
Полный release-процесс по-прежнему отвечает за сборку Core/Integration,
проверку происхождения пакета и release gate.

## Занятые файлы

`update-shell-files.ps1` сначала проверяет все три staging-файла `.new`, затем
заменяет DLL и схему с резервными копиями. Если очередная замена не удалась,
уже заменённые файлы восстанавливаются. При блокировке возвращается `pending`:
прежние файлы и COM-регистрация сохраняются, регистрация нового пакета не запускается.
Пользователь закрывает Проводник либо перезагружает Windows и **повторно запускает
установщик**. Автоматическая замена при перезагрузке не планируется.

При ошибке восстановления возвращается `error`, резервные копии сохраняются
для восстановления. Такой результат не считается успешным обновлением.

## Владение и удаление

После успешной регистрации схема и DLL получают защищённую запись `Owner.ini`
с каталогом установки и тремя SHA-256. Деинсталлятор сверяет её со своим пакетом.
Помощник дополнительно проверяет фактические хеши активной DLL и схемы, а также
все связанные CLSID и записи расширения. Результаты `ok`, `skipped` и `error`
различаются. Только `ok` разрешает удалять общие файлы и помощники.

Снятие регистрации схемы выполняется тем же процессом Windows PowerShell,
чья разрядность соответствует COM-регистрации. Ошибка схемы останавливает очистку.
При чужой, неполной или более новой регистрации компоненты сохраняются.
Консервативный пропуск может оставить общие файлы; ручное удаление таких файлов
до выяснения владельца не требуется. Миграция ProgramData сохраняет проверки
владения и не загружает старые DLL.

Файлы результатов административных операций находятся в защищённом
`Common Files\FictionBook Editor Next\Shell\InstallerTools`.

## Минимальная среда

Четыре помощника, запускаемых установщиком, используют синтаксис PowerShell 2.0
и API .NET 2.0/3.5. Убраны `::new()`, `$PSScriptRoot`, `IsNullOrWhiteSpace`,
`RegistryView`, `OpenBaseKey`, новые перегрузки `DeleteSubKeyTree` и `Dispose`.
Для реестра используется нативное представление соответствующего процесса.
При вызове из процесса другой разрядности помощник запускается повторно в
подходящем Windows PowerShell. PowerShell 7 для установки не требуется.
Статусы записываются в UTF-16 с BOM; пути Unicode не преобразуются в ANSI.

На Windows 7 пути системной интеграции ограничены обычными ограничениями
Win32/.NET той системы. Поддержка путей длиннее MAX_PATH не заявляется.
Фиксированное расположение в Common Files не зависит от длины пользовательского
каталога редактора. Ошибки доступа и слишком длинного пути прерывают операцию,
не разрешая последующее удаление общих файлов.

## Проверка 15.10.2026

- Общая команда сборки и BAT собрали setup из готовых stages; полная сборка
  редактора и полная CI-матрица не запускались. Вычисленные SHA-256 совпали
  с файлами соответствующего input. Отсутствующий stage, пересечение input/output
  и четыре вида неверных хешей были отклонены.
- `test-nsis-shell-maintenance.ps1` прошёл в PowerShell 7 и Windows PowerShell 5.1.
  Выполнены настоящие файловые замены и откат с открытой второй DLL, отказ при
  подменённом payload, регистрация/удаление в изолированной ветке HKCU,
  сохранение чужого каталога, нового пакета по тому же пути и чужой COM-регистрации,
  а также отказ очистки при ошибке снятия регистрации схемы.
- Выбор regsvr32 проверен для x86 Windows и обоих процессов x64 Windows.
  Перезапуск между настоящими x86/x64 Windows PowerShell проверен с заведомо
  неверным хешем: выполнение DLL и изменение системного реестра не допускались.
- Scope-пробы Current User / All Users / Portable и профильные NSIS contracts прошли.
- На Windows 11 пользователь подтвердил показ и активность повышенного тестового
  окна. После отказа UAC получен код 1223; исходное окно осталось доступным через
  кнопку панели задач. Взаимная блокировка не наблюдалась.

На машине уже имеются действующие COM-обработчики FBE. Полная установка и
удаление с записью в их HKLM-ключи не выполнялись; изолированные проверки не
считаются такой установкой. Загрузка DLL именно Проводником, фактическая
перезагрузка, другая учётная запись администратора и Windows 7 SP1 с исходной
PowerShell 2.0/.NET 3.5 остаются отдельными непроверенными сценариями.
