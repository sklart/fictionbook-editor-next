Окна отчёта показали версии 2.10 и 2.11. При повторном запуске каждого скрипта сохранённый FB2 совпал побайтово с результатом первого запуска (SHA-256 `373a6a33936fc46cca10971d361f725c168d89a2c8bb18ffe5615af14c6a3d4c`). Исходный файл и результаты сохранены в `build/community-feedback-rule67*.fb2`. Это конкретный сценарий, а не доказательство отсутствия побочных изменений на всех книгах.

В runtime-сценарий карточек добавлена проверка обоих новых номеров версий, текста изменения и состояния актуальности. В запуске через PowerShell 7 эти проверки дали `cleaning-values=1`, но весь сценарий завершился FAIL: `characteristic-dpi-matrix=0` и `info-selection=0`. Поэтому общий проход диалога карточек не заявляется; файлы неуспешного запуска сохранены в `build/community-feedback-temp`. Строгая Release Win32-сборка FBE после изменений прошла.

Исходное и новое правило в обоих скриптах соответственно:

```js
var re67 = new RegExp("(\\\d)(\\\s|"+nbspEntity+"){0,1}[oо0°](\\\s){0,1}[CС]([^A-zА-яЁё]){0,1}","g");
var re67 = new RegExp("(\\\d)(\\\s|"+nbspEntity+"){0,1}[oо°](\\\s){0,1}[CС](\\\s|[.,:;!?…»)<>&'}]|\\\]|\\\"|$)","g");
```

Скрипты сохранены в UTF-8 без BOM с исходными CRLF. Изменения вне правила ограничены заголовком версии, переменной версии, исторической записью и встроенной карточкой; другие правила и авторские сведения не переформатированы.
