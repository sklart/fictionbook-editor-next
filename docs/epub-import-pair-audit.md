# Проверка пары EPUB → FB2

Исходный EPUB, о котором сообщило сообщество 27.10.2026, пока не предоставлен.
Исправление его импорта не подтверждено. Импортёр этим изменением не меняется.

На копии EPUB выполнить штатный импорт FBE, сохранить результат отдельно и
сохранить предупреждения импортёра. Затем из корня репозитория:

```powershell
py.exe -3 tools/tests/compare-epub-fb2.py --epub source.epub --fb2 result.fb2 --report pair-audit.json
py.exe -3 tools/tests/test-compare-epub-fb2.py -v
```

Инструмент читает оба файла без изменения; отчёт не может перезаписать входной
файл. В отчёте есть SHA-256 входов, покрытие слов, последовательность хешей
текстовых блоков, порядок/уровни заголовков, сигнатуры явно размеченных сносок,
количество ссылок, неразрешённые внутренние ссылки и хеши изображений.
Текст книги и пути входных файлов в JSON не записываются.

Статус всегда `REVIEW`: совпадение слов не доказывает сохранность их порядка,
смысловой структуры, назначения ссылок или оформления. Отдельно проверить
главы, списки, таблицы, ссылки, возвраты из сносок, подписи и изображения.
TOC/backlinks, перенос сносок из non-spine XHTML, другие границы абзацев и
конвертация SVG/растров могут давать допустимые различия. Хеши разных целевых
ID EPUB и FB2 напрямую не сравниваются. Неразмеченные сноски требуют ручного
сопоставления. Невалидный XHTML/XML останавливает анализ с ошибкой.

После получения проблемной пары: сохранить хеши и настройки импорта,
воспроизвести расхождение, определить его минимальный фрагмент, добавить
допустимый по авторским правам fixture и проверку реального импортёра.
Только после RED/GREEN исправлять подтверждённый дефект.

На текущей базе прошли 55 `test-import-epub-fidelity.py` тестов и native COM
`test-import-epub-v2-runtime.ps1`. Эти проверки не подтверждают исправление
непредоставленной пользовательской книги.
