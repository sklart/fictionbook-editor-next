# FictionBook Editor Next 3.0.3

FictionBook Editor Next 3.0.3 — небольшое сервисное обновление после 3.0.2, сосредоточенное на исправлении проверки обновлений, установке поверх существующей версии, совместимости с Windows 7 и диагностике ошибок ImportEPUB.

Версия не добавляет крупных новых функций редактора, но устраняет несколько проблем, которые могли мешать нормальному обновлению или затруднять поиск причины ошибки.

## Главное в 3.0.3

* Исправлена проверка обновлений через GitHub.
* Устранено несколько независимых причин ложного сообщения **«Ошибка загрузки»**.
* Улучшена диагностика ошибок при импорте EPUB.
* Установщик корректнее обновляет занятые Проводником shell-библиотеки.
* Устранена ещё одна несовместимость с Windows 7.
* Улучшена страница выбора компонентов установщика.
* Расширено окно «О программе».
* Усилены автоматические проверки регистрации ImportEPUB и вариантов установки `.fb2`-интеграции.

## Исправлена проверка обновлений

Основная пользовательская проблема, исправленная в 3.0.3, связана с командой проверки обновлений в окне **«О программе»**.

В некоторых случаях FBE Next успешно загружал `update.xml` с GitHub, но всё равно показывал:

**«Ошибка загрузки»**

В 3.0.3 исправлено сразу несколько причин такого поведения.

### Корректная обработка GitHub/raw

Механизм загрузки стал устойчивее к HTTP-ответам без явно указанного `Content-Length`.

Такие ответы допустимы и могут использоваться GitHub, поэтому отсутствие этого заголовка больше не считается признаком неудачной загрузки.

### Исправлена обработка конечного URL

После HTTPS-переадресации FBE проверяет фактический адрес загруженного файла.

Из-за ошибки при выделении Unicode-буфера для `INTERNET_OPTION_URL` итоговый URL мог считываться неправильно или оставаться пустым.

В результате нормальный HTTPS-ответ GitHub ошибочно признавался недоверенным.

В 3.0.3 размер Unicode-буфера рассчитывается правильно.

### Исправлен разбор `update.xml`

Исправлено чтение актуального формата манифеста:

```xml
<FBE>
    <Version>...</Version>
</FBE>
```

Корректно загруженный манифест больше не должен приводить к ложной ошибке только из-за его структуры.

Если установлена последняя версия, FBE теперь должен нормально сообщать об этом вместо **«Ошибка загрузки»**.

## Диагностика проверки обновлений

Диагностический журнал проверки обновлений сохраняется в:

`%LOCALAPPDATA%\FBE\update-check-trace.log`

Он может использоваться для выяснения причины ошибки, если соединение с GitHub или обработка манифеста всё же завершаются неудачно.

## Улучшено окно «О программе»

Окно **«О программе»** стало шире.

Полный адрес репозитория FictionBook Editor Next теперь помещается без визуального обрезания.

Изменение небольшое, но особенно заметно после перехода проекта на более длинное имя `fictionbook-editor-next`.

## Улучшена диагностика ImportEPUB

ImportEPUB теперь перехватывает непредвиденные COM-исключения внутри самого плагина.

Ранее пользователь в некоторых случаях мог получить только общее сообщение FBE:

`COM Error`

без указания, на каком этапе произошёл сбой.

Теперь сообщение дополнительно показывает стадию импорта, например:

* выбор EPUB-файла;
* обработка EPUB;
* преобразование EPUB в FB2;
* создание FB2 DOM-документа;
* другие этапы внутренней обработки.

Это не устраняет автоматически все возможные ошибки повреждённых или нестандартных EPUB, но значительно упрощает диагностику конкретной причины сбоя.

## Проверка регистрации ImportEPUB

В релизный контур добавлена отдельная автоматическая проверка регистрации `ImportEPUB.dll`.

Она контролирует:

* 32-битную COM-регистрацию плагина;
* наличие MSXML6;
* доступность `IFileOpenDialog`;
* доступность `Shell.Application`.

Это позволяет обнаруживать ещё до публикации релиза ситуацию, когда ImportEPUB не запускается с ошибкой вида:

`80040154 — Класс не зарегистрирован`

Для обычного пользователя это означает меньший риск получить установленный, но фактически недоступный плагин импорта.

## Обновление поверх установленной версии

Исправлен неприятный сценарий обновления FBE Next при установленной интеграции с Проводником Windows.

Библиотеки:

* `FBShell.dll`;
* `FBShell64.dll`

могут оставаться загруженными процессом `explorer.exe`.

Раньше при попытке заменить такой файл установщик мог предложить пользователю вручную выбрать **«Пропустить»**, после чего установленный набор файлов мог оказаться смешанным из старой и новой версии.

В 3.0.3, если shell-библиотека занята Проводником, установщик использует **отложенную замену файла после перезагрузки Windows**.

Это делает обновление поверх существующей установки заметно надёжнее.

## Улучшена страница компонентов установщика

Раздельные параметры `.fb2`-интеграции были добавлены ранее, но их длинные названия занимали много места на странице компонентов.

В 3.0.3 изменена компоновка страницы:

* описание выбранного компонента перенесено вниз;
* дерево компонентов получило больше полезной ширины;
* длинные названия параметров `.fb2`-интеграции меньше обрезаются;
* описания сделаны компактнее.

Это особенно полезно для таких пунктов, как свойства и миниатюры FB2 в Проводнике.

## Проверка вариантов `.fb2`-интеграции

Для уже существующих отдельных опций интеграции добавлена автоматизированная постустановочная диагностика.

Проверяются сценарии:

* без интеграции `.fb2`;
* только назначение FBE Next приложением для FB2;
* только команда **«Проверить FB2 на ошибки»**;
* только свойства и миниатюры в Проводнике;
* полный набор интеграции.

Особенно проверяется, что команду:

**«Проверить FB2 на ошибки»**

можно установить отдельно, **не меняя текущую программу для открытия FB2 и иконку файлов**.

Это в основном изменение контроля качества релиза, но оно защищает пользовательские настройки Windows от случайной перезаписи установщиком.

## Улучшена совместимость с Windows 7

Из FBE удалён прямой вызов:

`PathCchRemoveFileSpec`

Он приводит к зависимости от:

`api-ms-win-core-path-l1-1-0.dll`

которая отсутствует в стандартной Windows 7.

Вместо него снова используется совместимая функция:

`PathRemoveFileSpecW`

из системной `SHLWAPI.dll`.

Это устраняет одну из причин, по которой FBE Next мог не запускаться на Windows 7 с сообщением об отсутствующей DLL или точке входа.

Важно: специального отдельного Win7-релиза в 3.0.3 ещё нет — он появляется начиная с 3.0.4.

## Очистка после обновления WTL

После перехода проекта на WTL 10.0.1 удалены оставшиеся неиспользуемые legacy-заголовки:

* `atlresce.h`;
* `atlwince.h`;
* `tmschema.h`.

Первые два относились в том числе к давно устаревшему Windows CE-контуру.

Для пользователя это изменение ничего напрямую не меняет, но уменьшает объём исторического кода и делает состав используемой WTL более понятным.

## Внутренние проверки релиза

Для 3.0.3 дополнительно усилена автоматическая проверка:

* COM-регистрации ImportEPUB;
* системных COM-зависимостей ImportEPUB;
* различных вариантов `.fb2`-интеграции установщика;
* корректности установки shell-компонентов;
* поведения обновления существующей установки.

Эти изменения предназначены прежде всего для предотвращения повторного появления уже найденных ошибок.

## Что изменилось по сравнению с 3.0.2

3.0.3 — именно **исправляющий сервисный релиз**, а не очередной функциональный этап развития FBE Next.

Основные отличия от 3.0.2:

* исправлена проверка обновлений через GitHub;
* исправлен разбор `update.xml`;
* устранена ошибка обработки конечного HTTPS URL;
* расширено окно «О программе»;
* ImportEPUB получил более информативные сообщения об ошибках;
* обновление shell-компонентов стало безопаснее;
* улучшена страница компонентов установщика;
* устранена зависимость FBE от `PathCchRemoveFileSpec` на Windows 7;
* усилены автоматические проверки установки и ImportEPUB.
