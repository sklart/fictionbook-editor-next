# FictionBook Editor Next 3.0.7

FictionBook Editor Next 3.0.7 — стабильный выпуск, продолжающий развитие 3.0.7 RC2.

По сравнению с **3.0.7 RC2** основное внимание уделено режиму «Код», импорту изображений, поддержке FBD, дальнейшему развитию редактора таблиц и защите документов от повреждения при сохранении.

## Главное

* Добавлено контекстное автодополнение FB2/XML в режиме «Код» на основе схемы FictionBook.
* XML-ошибки теперь показываются непосредственно возле проблемной строки.
* Существенно улучшена работа Source editor с большими документами.
* Добавлен импорт современных форматов изображений: WebP, JPEG 2000, AVIF, HEIC/HEIF, а также BMP, GIF и TIFF.
* Добавлена поддержка файлов описания FictionBook `.fbd`.
* Редактор таблиц научился корректно работать с `rowspan` и `colspan`.
* Добавлены массовые преобразования выбранных ячеек таблицы между `TD` и `TH`.
* Усилена защита таблиц и бинарных вложений от повреждения при сохранении.
* ExportHTML получил полноценный автономный HTML-режим.
* Исправлен ряд старых проблем MSHTML, скриптов и вспомогательных утилит.
* Scintilla обновлена до **5.6.6**, Lexilla — до **5.5.3**.

# Режим «Код»

## Автодополнение FB2 по схеме

В Source editor появилось контекстное автодополнение, использующее метаданные, сформированные из схемы FictionBook.

Редактор предлагает:

* допустимые FB2-элементы;
* дочерние элементы с учётом текущей структуры документа;
* допустимые атрибуты;
* закрывающие теги;
* значения некоторых атрибутов;
* существующие `id` документа для XLink-ссылок.

Например, после начала нового элемента редактор предлагает только допустимые для текущего родительского элемента теги, а при вводе `href="#..."` может показать идентификаторы, реально существующие в открытом FB2.

Учитываются стандартные варианты XLink:

* `l:href`;
* `xlink:href`;
* пользовательский namespace-префикс, если он действительно связан с XLink.

Подсказки подавляются внутри XML-комментариев, CDATA и processing instructions и не используют слова художественного текста.

## XML-ошибки возле проблемной строки

Результат проверки XML теперь можно увидеть непосредственно в Source editor.

Первая обнаруженная SAX/schema-ошибка отображается как аннотация возле соответствующей строки.

Аннотация автоматически очищается:

* перед новой проверкой;
* после успешной проверки;
* после исправления исходного текста;
* при смене состояния документа.

Это сокращает время поиска проблемного участка в больших FB2.

## Улучшена работа с большими документами

Оптимизированы горячие пути Scintilla:

* уменьшено число лишних обновлений Source editor;
* поле номеров строк пересчитывается только при изменении числа строк;
* подсветка парных XML-тегов не пересчитывается при простой прокрутке;
* сокращено число ненужных уведомлений Scintilla;
* часть операций подсветки переведена на Direct API;
* улучшено восстановление выделения и прокрутки при Undo/Redo.

Добавлены отдельные memory- и performance-проверки больших XML-документов.

## Невидимые Unicode-символы

В настройках режима «Код» можно включить явное отображение:

* NBSP;
* narrow NBSP;
* soft hyphen;
* zero-width space;
* zero-width non-joiner;
* zero-width joiner;
* word joiner;
* BOM.

Функция меняет только отображение: содержимое FB2 остаётся неизменным.

Доступны два стиля:

### Символы как в Word

Компактные обозначения для часто встречающихся символов, например:

* NBSP — `°`;
* soft hyphen — `¬`.

### Текстовые метки

Используются обозначения `NBSP`, `SHY`, `ZWSP`, `ZWNJ`, `ZWJ`, `NNBSP`, `WJ`, `BOM`.

## Исправлен поиск и замена

После команды «Заменить» Source editor больше не принудительно продолжает поиск вниз.

Если выбран поиск вверх, это направление сохраняется и после замены.

Корректно обрабатывается также переход через начало и конец документа.

## Scintilla и Lexilla

Редакторный runtime обновлён до:

* **Scintilla 5.6.6**;
* **Lexilla 5.5.3**.

При модернизации отдельно оценивались новые возможности Scintilla. Возможности, не дающие практического выигрыша или ухудшающие производительность FBE, не включались только ради использования нового API.

# Импорт изображений

В 3.0.7 появился новый механизм импорта изображений в FB2.

## Поддерживаемые исходные форматы

FBE может добавлять:

* JPEG / JPG;
* PNG;
* WebP;
* JPEG 2000 (`.jp2`, `.j2k`);
* BMP;
* GIF;
* TIFF;
* AVIF;
* HEIC;
* HEIF.

Современные и неподходящие непосредственно для FB2 форматы автоматически преобразуются в JPEG или PNG.

## Настройки преобразования

Можно выбрать выходной формат:

* **Авто**;
* **JPEG**;
* **PNG**.

Также настраивается качество JPEG.

В автоматическом режиме FBE учитывает прозрачность изображения и выбирает подходящий формат.

## JPEG и PNG без повторного сжатия

Если исходный JPEG или PNG уже подходит для FB2, его можно сохранить без перекодирования.

Это позволяет:

* избежать дополнительной потери качества JPEG;
* не увеличивать PNG без необходимости;
* ускорить импорт;
* сохранить исходные бинарные данные.

## Прозрачность

Прозрачные изображения автоматически могут сохраняться как PNG.

Если пользователь принудительно выбирает JPEG для изображения с alpha-каналом, FBE запрашивает подтверждение преобразования на непрозрачный фон вместо молчаливой потери прозрачности.

## WebP

Поддерживаются обычные WebP, включая изображения с прозрачностью.

Анимированный WebP намеренно не импортируется как обычная статическая картинка и выдаёт понятное сообщение.

## JPEG 2000

Добавлена поддержка:

* JP2;
* J2K;
* цветных изображений;
* изображений с alpha-каналом.

Дополнительно исправлена работа с JPEG 2000, использующими различную геометрию компонентов.

## AVIF / HEIC / HEIF

Добавлена полноценная цепочка декодирования HEIF-семейства.

Проверяются в том числе:

* 10-bit AVIF;
* прозрачность;
* цвет;
* ориентация;
* crop/display dimensions HEIC;
* корректное распознавание HEIF container brands.

Видео-контейнеры не должны ошибочно распознаваться как HEIF-изображения.

## GIF и TIFF

Поддерживается импорт обычных статических GIF и одностраничных TIFF.

Пока не поддерживаются:

* анимированные GIF;
* многостраничные TIFF.

Для таких случаев выдаётся отдельное сообщение.

## Надёжность

Добавлена обработка:

* повреждённых изображений;
* слишком больших изображений;
* ошибок декодирования;
* ошибок кодирования;
* нехватки памяти;
* ошибок ориентации;
* проблем прозрачности.

После импорта корректно обновляется preview-кэш изображений.

Также предотвращаются коллизии логических имён изображений, если исходные файлы из разных каталогов имеют одинаковые имена.

# Поддержка FBD

В FBE Next добавлена работа с файлами **FictionBook Description (`.fbd`)**.

FBD используется для XML-описания книги без обязательного обычного текстового `body`.

## Открытие и сохранение

`.fbd` теперь:

* отображается в диалогах открытия;
* можно открыть перетаскиванием;
* можно открыть через навигацию FBE;
* корректно сохраняется снова как `.fbd`;
* учитывается в MRU.

Для description-only документа визуальный редактор создаёт временное рабочее Body-представление, необходимое для интерфейса FBE, но оно не записывается в файл, если пользователь его фактически не заполнил.

## Проверка FBD

Для FBD введена отдельная политика проверки.

Программа различает:

* обычный FB2;
* описание FBD;
* некорректную структуру FictionBook.

Для корректного description-only FBD не выдаётся ложная ошибка о невозможности пройти обычную FB2 schema validation.

## Интеграция с Windows

Установщик получил отдельную опцию:

**«Использовать FBE Next для файлов описания .fbd»**

Ассоциация `.fbd` отделена от `.fb2`, FBV и shell-обработчиков FB2.

При удалении FBE Next установщик старается восстановить предыдущую ассоциацию `.fbd`, а не безусловно удалить пользовательскую настройку.

# Таблицы

В RC2 появился основной визуальный редактор таблиц. В финальной 3.0.7 его реализация была значительно усилена.

## Корректная работа rowspan и colspan

Структурные команды теперь используют логическую сетку таблицы и учитывают объединённые ячейки.

Корректно работают:

* вставка строки выше;
* вставка строки ниже;
* удаление строки;
* вставка столбца слева;
* вставка столбца справа;
* удаление столбца.

Если операция проходит через объединённую ячейку, соответствующий `rowspan` или `colspan` корректируется вместо создания неправильной структуры.

При удалении строк и столбцов лишний span также очищается.

## Массовое преобразование TD / TH

Для выделенного диапазона таблицы появились команды:

* **Сделать ячейками заголовка**;
* **Сделать обычными ячейками**.

Таким образом можно преобразовать сразу строку, столбец или прямоугольный диапазон между `TD` и `TH`.

При преобразовании сохраняются:

* содержимое ячейки;
* `id`;
* `style`;
* `rowspan`;
* `colspan`;
* `align`;
* `valign`;
* другие значимые атрибуты.

Операция поддерживает Undo/Redo как единое действие.

## Сохранение структуры таблицы

Добавлены дополнительные защитные проверки сериализации.

Перед записью FBE контролирует, что:

1. таблица не исчезла при нормализации визуального DOM;
2. таблица попала в итоговый XML;
3. её логическая структура не изменилась неожиданно.

Если обнаруживается потеря структуры, сохранение завершается ошибкой вместо записи повреждённого FB2.

## Проверки больших таблиц

Добавлены production-тесты:

* сложных `rowspan`/`colspan`;
* последовательных структурных операций;
* повторного редактирования без перезагрузки;
* массового TD/TH;
* таблиц на сотни строк и тысячи ячеек;
* повторного сохранения.

# Защита бинарных данных и сохранения

## Base64

Усилено сохранение `<binary>`.

Временные служебные свойства MSXML больше не должны попадать в XML как:

* `dt:dt`;
* `urn:schemas-microsoft-com:datatypes`.

После сохранения binary проверяется не только как текст Base64, но и по декодированному содержимому.

## Production round-trip

Для таблиц и бинарных вложений добавлены проверки полного цикла:

**открытие → Save → повторное открытие → повторный Save**

После каждого этапа проверяются структура и данные.

Для binary сравниваются:

* `id`;
* `content-type`;
* размер;
* SHA-256 декодированного содержимого.

## Сохранение встроенных изображений

Усилена операция сохранения бинарного изображения на диск.

Файлы записываются более безопасно, а пакетный режим не должен:

* неожиданно открывать интерактивные диалоги;
* без разрешения уничтожать существующий файл;
* оставлять частично записанный результат.

# ExportHTML

## Автономный HTML

ExportHTML получил новый режим **«Автономный HTML»**.

Иллюстрации в таком документе встраиваются прямо в HTML в виде `data:` URI.

В результате получается один переносимый `.html` без соседней папки изображений.

## Пользовательский CSS

В диалоге экспорта можно указать собственный CSS.

Он добавляется к генерируемому документу и позволяет менять оформление без редактирования штатного XSL.

## Размер изображений

Добавлены параметры максимальной:

* ширины;
* высоты

изображений в экспортируемом HTML.

# Визуальный редактор

## Исправлено самопроизвольное создание ссылок

Отключён встроенный MSHTML `AutoUrlDetect`.

Ранее MSHTML мог после смены фокуса самостоятельно превратить текст вроде:

`\\word`

в `file://`-ссылку.

Теперь ссылка в FB2 появляется только после явного действия пользователя.

## Исправлено выделение изображений

Устранён старый сценарий, при котором MSHTML на короткое время переводил выбранное изображение в специальный Control selection и мог вернуть COM-ошибку при синхронизации дерева документа.

Теперь выбранный `IMG` корректно сопоставляется с логическим контейнером изображения, а временные ошибки MSHTML не вызывают модальное окно с COM Error.

Это особенно важно при выборе иллюстраций и взаимодействии с полосами прокрутки.

## Улучшена надёжность main.js

Исправлен ряд исторических проблем JavaScript визуального редактора:

* обновление списка изображений после изменения binary;
* кэш размеров изображений;
* preview/full-image logic;
* устаревшие таймеры предпросмотра;
* обновление всех экземпляров удаляемого изображения;
* работа с изменяемыми DOM collections;
* несколько ошибочных вызовов MSHTML API;
* экранирование HTML;
* отдельные операции с заголовками и эпиграфами.

# Слова и орфография

## Большие Words.xml

Окно «Слова» переведено на виртуальный owner-data ListView.

Для больших пользовательских словарей это уменьшает:

* расход памяти;
* число Windows UI-объектов;
* время массового выделения;
* время удаления большого количества элементов.

Временные объекты, создаваемые при чтении `Words.xml`, теперь освобождаются после загрузки.

## Орфография

Сохраняются улучшения работы с soft hyphen, а производительность проверки длинных документов дополнительно покрыта отдельными smoke-сценариями.

# Горячие клавиши и меню

## Горячая клавиша «Настройки»

Команда **Сервис → Настройки** теперь участвует в общей системе настраиваемых hotkeys.

Для исходной конфигурации добавлено сочетание:

**Ctrl+,**

Его можно переназначить через обычный механизм горячих клавиш.

Старые `Hotkeys.xml`, в которых этой команды ещё нет, продолжают загружаться без сброса остальных назначений.

## Мнемоники меню

Пересмотрены `Alt`-мнемоники основных меню для поддерживаемых языков.

Добавлены автоматические проверки, предотвращающие:

* отсутствие `&`-маркера;
* несколько маркеров одновременно;
* конфликт одинаковых mnemonic-key у соседних пунктов меню.

# Стабильные команды скриптов

Для встроенных и пользовательских скриптов стабилизированы command ID.

Идентификатор связывается с относительным путём скрипта и сохраняется в настройках.

Благодаря этому добавление, удаление или изменение порядка скриптов не должно приводить к тому, что сохранённая горячая клавиша или кнопка панели внезапно запускает другой скрипт.

# Вспомогательные утилиты

## ArchHandler

ArchHandler окончательно переведён с Delphi на C++/WinAPI.

Сохранена работа с:

* ZIP;
* RAR;
* `.fb2.zip`;
* `.fb2.rar`;
* отдельными приложениями для FB2-архивов и обычных архивов;
* пользовательскими шаблонами аргументов.

Улучшено экранирование Unicode-путей и аргументов командной строки.

ArchHandler теперь собирается самим release pipeline отдельно для нужного целевого профиля, включая Windows 7-compatible вариант.

Исправлена очистка его регистрации и кодировка сообщений.

## FB2Recode

Утилита получила дополнительные исправления.

### Реальная отмена пакетной операции

Кнопка отмены теперь действительно прекращает обработку между файлами.

Необработанные документы учитываются как пропущенные.

### Корректная Windows-1251

Проверка представимости текста использует точный набор символов CP1251, а не приблизительные Unicode-диапазоны.

### Выбор файла

Удалена зависимость от устаревшего `UserAccounts.CommonDialog`, отсутствующего на части современных Windows.

Файл выбирается штатным файловым контролом HTA.

## Save Sections As Separate Documents

Финальная замена созданного файла стала безопаснее.

Новый файл:

1. записывается во временное имя;
2. проверяется как XML/FictionBook;
3. только после этого заменяет существующий.

Если финальная операция завершается ошибкой, старая версия восстанавливается.

Также исправлена очистка списка разделов в старом JScript-коде утилиты.

## FB2CheckContentTypes

Исторические варианты проверки объединены в одну утилиту.

Она:

* использует современный MSXML с fallback;
* безопасно загружает XML;
* проверяет Base64;
* определяет фактический формат изображения по сигнатуре;
* сравнивает его с `content-type`;
* считает совпадения, ошибки и повреждённые binary;
* позволяет копировать или сохранять отчёт.
