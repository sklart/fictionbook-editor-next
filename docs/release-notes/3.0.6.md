# FictionBook Editor Next 3.0.6

FictionBook Editor Next 3.0.6 — обновление, направленное прежде всего на удобство повседневного редактирования, работу с пользовательскими скриптами, сохранение документов, локализацию и установку экспортных плагинов.

В этой версии улучшено переключение между визуальным и XML-представлением книги, расширены настройки FBE Next и API пользовательских JavaScript-скриптов, добавлена подробная диагностика их ошибок и исправлен ряд проблем установщика.

Для Windows 7 SP1 по-прежнему выпускается отдельная совместимая сборка.

## Главное в 3.0.6

* Улучшен переход между режимами **«Тело» и «Код»** с переносом выделения в обоих направлениях.
* Добавлена настройка показа **полного пути к открытому FB2 в заголовке окна**.
* Добавлено управляемое создание резервных копий `.bak`.
* Пользовательские JavaScript-скрипты получили API для определения **пути, имени файла и каталога открытой книги**.
* Полностью документирован API `window.external`.
* Значительно улучшена диагностика ошибок пользовательских JavaScript-скриптов.
* Экспортные плагины HTML, DOCX и EPUB теперь устанавливаются без необходимости административной регистрации.
* Исправлены проблемы русской и украинской локализации.
* Улучшены интерфейс и локализация установщика.

## Переключение между «Телом» и «Кодом»

Существенно улучшено сохранение позиции пользователя при переключении между визуальным редактором и исходным XML.

Теперь FBE переносит выделение:

* из **«Тела» в «Код»**;
* из **«Кода» обратно в «Тело»**.

При переходе к XML редактор автоматически прокручивается к соответствующему фрагменту исходного текста.

Алгоритм учитывает:

* XML-теги внутри выделения;
* сущности XML;
* пробельные символы и неразрывные пробелы;
* выделения, пересекающие несколько абзацев;
* заголовки и другие структурные элементы FB2.

Если выделение в Source невозможно однозначно сопоставить с отображаемым текстом, FBE безопасно отказывается от восстановления диапазона вместо использования устаревшего выделения из режима «Тело».

Это особенно удобно при чередовании визуального редактирования книги и ручной правки её XML.

## Полный путь к файлу в заголовке окна

На вкладке **«Настройки FBE Next»** появилась новая опция:

**«Показывать полный путь к файлу в заголовке окна»**

По умолчанию она отключена.

При включении вместо одного имени книги FBE может показывать её полный путь, например:

`D:\Книги\Редактирование\Автор\Книга.fb2`

Если путь не помещается в заголовке окна, он автоматически сокращается, при этом сохраняется имя самого файла.

Функция особенно полезна при одновременной работе с несколькими одноимёнными FB2 из разных каталогов.

## Резервные копии `.bak`

В настройках FBE Next добавлено управление созданием резервной копии при сохранении существующей книги.

По умолчанию создание `.bak` **включено**.

При перезаписи:

`book.fb2`

предыдущая версия документа может сохраняться как:

`book.fb2.bak`

Отключение `.bak` не отключает безопасный механизм записи самого FB2: сохранение по-прежнему выполняется через временный файл с последующей заменой исходного файла.

Таким образом, пользователь может отказаться от дополнительных резервных файлов, не теряя защиту от повреждения документа при неудачном сохранении.

## Новые возможности пользовательских скриптов

API `window.external` расширен методами получения информации об открытой книге:

* `GetDocumentFilePath()` — полный путь к FB2;
* `GetDocumentFileName()` — имя файла вместе с расширением;
* `GetDocumentDirectory()` — каталог открытого файла.

Например:

```js
var fullPath = window.external.GetDocumentFilePath();
var fileName = window.external.GetDocumentFileName();
var directory = window.external.GetDocumentDirectory();
```

Это позволяет пользовательским скриптам создавать отчёты, дополнительные файлы или выполнять другие операции относительно каталога текущей книги без ручного задания путей.

Для нового документа, который ещё ни разу не сохранялся, методы возвращают пустую строку.

## Документация API скриптов

Подготовлен отдельный расширенный справочник API пользовательских JavaScript-скриптов.

Документированы **28 методов `window.external` и свойство `inflateBlock`**, включая:

* сигнатуры;
* назначение;
* параметры;
* возвращаемые значения;
* ограничения;
* примеры использования.

Добавлено оглавление с быстрыми переходами между методами.

Это должно упростить как создание новых скриптов для FBE Next, так и поддержку большого существующего набора сценариев FictionBook Editor.

## Диагностика ошибок JavaScript

Значительно переработаны сообщения об ошибках пользовательских `.js`-скриптов.

FBE теперь различает как минимум:

* ошибку чтения файла;
* синтаксическую ошибку;
* ошибку выполнения.

В диагностическом окне могут отображаться:

* тип ошибки;
* этап, на котором она произошла;
* имя скрипта;
* полный путь;
* номер строки;
* столбец;
* фрагмент исходного кода;
* указатель на проблемное место;
* исходное сообщение JScript;
* HRESULT / код ошибки.

Полученные сведения можно **скопировать в буфер обмена** и приложить к сообщению об ошибке на GitHub.

Это особенно полезно при работе со сторонними и старыми скриптами, когда прежнее короткое сообщение движка практически не позволяло понять причину сбоя.

## Экспорт HTML, DOCX и EPUB

Изменена регистрация экспортных плагинов:

* ExportHTML;
* ExportDOCX;
* ExportEPUB.

Регистрация выполняется в пользовательской части реестра Windows, поэтому установка экспортных компонентов больше не должна требовать административной COM-регистрации.

Это также уменьшает количество проблем при установке FBE Next в пользовательском режиме.

## ExportDOCX

Исправлен обнаруженный PVS-Studio проблемный участок обработки заголовков сносок со знаком:

`№`

Устранено использование некорректного многосимвольного литерала.

Изменение в первую очередь техническое, но исключает потенциально неоднозначное поведение при обработке таких заголовков.

## Настройки и интерфейс

Все страницы окна настроек приведены к единому оформлению.

Используется единый шрифт:

**Tahoma 8**

за основу взято оформление страницы **«Слова»**.

Правило распространяется в том числе на русскую и украинскую локализованные resource DLL.

Это устраняет заметные различия размеров и шрифтов между отдельными вкладками настроек.

## Русская и украинская локализация

Исправлены повреждённые строки встроенных русской и украинской локализаций.

В частности, последовательности вопросительных знаков больше не должны появляться вместо:

* подписей;
* подсказок панели инструментов;
* названий команд;
* элементов настроек.

Локализованные DLL FBE теперь формируются непосредственно в:

`Lang\ru-RU`

и

`Lang\uk-UA`

Устаревшие дубли `res_rus.dll` и `res_ukr.dll` в корне программы больше не входят в release-пакеты.

## Установщик

Улучшена страница выбора компонентов.

* Увеличена область описания выбранного компонента.
* Слишком длинные пояснения сокращены.
* Тексты выровнены для поддерживаемых локализаций.
* Описание штатного комплекта скриптов больше не содержит устаревшую ссылку на Jurgennt и корректно указывает на комплект от сообщества.

Дополнительно сборка установщика переведена на Unicode-вариант NSIS, что устраняет повреждение русских сообщений в некоторых сценариях установки.

## Внутренние изменения

Для выпуска 3.0.6 также расширены автоматические проверки проекта.

Добавлены regression-тесты для:

* переноса выделения между «Телом» и «Кодом»;
* API пути открытого документа для скриптов;
* отображения полного пути в заголовке окна;
* диагностики ошибок JavaScript;
* расположения локализованных DLL;
* пользовательской регистрации экспортных плагинов;
* страницы компонентов установщика.

Release-проверки дополнительно контролируют структуру языковых пакетов и отсутствие устаревших копий локализованных DLL в корне программы.

## Что особенно изменилось по сравнению с 3.0.5

Если кратко, 3.0.6 сосредоточен не на обновлении сторонних библиотек или крупных новых форматах, а на улучшении рабочих сценариев редактора:

* переключаться между визуальным представлением и XML стало удобнее;
* стало проще различать одинаковые файлы из разных каталогов;
* резервные `.bak` теперь можно настраивать;
* пользовательские скрипты получили больше информации о текущем документе;
* разработка и отладка скриптов стала значительно удобнее;
* экспортные плагины меньше зависят от административных прав;
* устранён ряд проблем локализованного интерфейса и установщика.
