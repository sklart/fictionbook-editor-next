# FictionBook Editor Next 3.0.1

FictionBook Editor Next 3.0.1 — первый сервисный релиз после 3.0.0.

Версия в основном укрепляет техническую основу новой ветки: обновляет библиотеку интерфейса WTL, исправляет проверку обновлений через GitHub, устраняет регрессию сборки shell-компонента и существенно улучшает документацию проекта.

Новых крупных функций редактирования FB2 в этом выпуске нет.

## Главное в 3.0.1

* WTL обновлена с исторической версии 8.1 до **WTL 10.0.1**.
* Исправлено ложное сообщение **«Ошибка загрузки»** при проверке обновлений через GitHub.
* Восстановлена корректная clean- и standalone-сборка `FBShell`.
* Автоматическая проверка сторонних библиотек теперь охватывает и WTL.
* README значительно расширен и дополнен наглядными скриншотами возможностей FBE Next.
* Уточнена политика поддержки различных версий Windows.

## WTL обновлена до 10.0.1

Встроенный комплект **Windows Template Library (WTL)** обновлён с исторической версии 8.1 до WTL 10.0.1.

WTL используется во многих частях пользовательского интерфейса FictionBook Editor:

* окнах;
* диалогах;
* меню;
* панелях инструментов;
* стандартных Windows-контролах.

Для пользователя это обновление не добавляет отдельной новой команды или режима работы — внешний интерфейс должен оставаться привычным.

Главный эффект находится внутри программы:

* убирается значительная часть технического долга старой UI-библиотеки;
* улучшается совместимость исходного кода с современными ATL и Visual Studio;
* создаётся более надёжная основа для последующих доработок интерфейса;
* упрощается дальнейшее сопровождение Windows-кода.

В комплект WTL также добавлены отсутствовавшие ранее современные заголовки, включая:

* `atldwm.h`;
* `atlribbon.h`.

## WTL включена в систему обновления зависимостей

WTL теперь отслеживается тем же механизмом, который используется для других сторонних компонентов FBE Next.

Автоматизированные инструменты могут:

* определять используемую версию WTL;
* проверять наличие новой версии;
* загружать upstream-архив;
* подготавливать обновление встроенного комплекта.

Таким образом, WTL больше не является исторической библиотекой, обновляемой вручную и нерегулярно.

## Исправлена проверка обновлений через GitHub

Исправлена одна из причин ложного сообщения:

**«Ошибка загрузки»**

в окне **«О программе»**.

Некоторые корректные HTTP/HTTPS-ответы GitHub могут передаваться без явного заголовка:

`Content-Length`

Ранее FBE Next мог считать отсутствие известной заранее длины файла ошибкой и отклонять такой ответ, даже если `update.xml` фактически был доступен.

В 3.0.1 отсутствие `Content-Length` само по себе больше не считается ошибкой.

Для ответов, где длина известна, проверка размера сохраняется.

Это делает встроенную проверку обновлений устойчивее к реальному поведению GitHub и промежуточных HTTP-серверов.

## Исправлена сборка FBShell после обновления WTL

После перехода на WTL 10.0.1 обнаружилась регрессия в `FBShell` — компоненте интеграции FB2 с Проводником Windows.

Исправлены две связанные проблемы.

### CString

Общие вспомогательные функции shell-модуля теперь явно используют:

`ATL::CString`

вместо устаревшей привязки к `WTL::CString`.

Это соответствует современной структуре WTL/ATL.

### Независимый путь к WTL

Проект `FBShell` больше не рассчитывает, что он обязательно собирается из основного solution с корректным `$(SolutionDir)`.

Путь к WTL теперь определяется относительно самого проекта.

Благодаря этому `FBShell` снова корректно собирается:

* вместе со всем FictionBook Editor Next;
* отдельно;
* в чистой CI-среде GitHub Actions.

Для пользователя это не новая функция Проводника, а устранение риска получить релиз с неправильно собранным shell-компонентом.

## Проверена работа после обновления WTL

После перехода на WTL 10.0.1 прогоняется существующий набор проверок, охватывающий в том числе:

* запуск FBE;
* FictionBook Validator;
* загрузку FBShell;
* свойства и миниатюры FB2;
* ExportEPUB;
* пользовательские строки плагинов;
* полную Release-сборку;
* проверку релизных файлов.

Обновление фундаментальной UI-библиотеки поэтому проверяется не только фактом успешной компиляции.

## Лучше описаны возможности FictionBook Editor Next

README теперь нагляднее объясняет основные отличия Next от исходного FictionBook Editor:

* современный установщик;
* интеграцию с Проводником;
* свойства и миниатюры FB2;
* FictionBook Validator;
* ExportDOCX;

Это делает страницу проекта значительно полезнее для пользователя, который знакомится с FBE Next впервые.

## Уточнена поддержка Windows

В документации впервые явно сформулирована политика совместимости для новой ветки.

На момент 3.0.1 основным целевым контуром считаются:

* Windows 10;
* Windows 11.

Для них проверяются основные функции установки и интеграции с системой.

Windows 7 SP1 и Windows 8.1 на этом этапе рассматриваются как системы с ожидаемой совместимостью при наличии необходимых обновлений и runtime-компонентов.

Windows XP и Windows Vista не входят в стандартный поддерживаемый контур FBE Next.

Отдельной специальной Win7-сборки в 3.0.1 ещё нет — она появится позднее, начиная с 3.0.4.

## Что не изменилось

3.0.1 не является функциональным обновлением редактора.

По сравнению с 3.0.0 здесь не добавляются новые:

* возможности редактирования FB2;
* плагины импорта или экспорта;
* batch-конвертеры;
* функции Проводника;
* возможности FBV.

Большинство этих новшеств относится непосредственно к большому релизу 3.0.0.

3.0.1 закрепляет его техническую основу и исправляет обнаруженные после выпуска проблемы.

## Что изменилось по сравнению с 3.0.0

Основные отличия:

* WTL 8.1 заменена на WTL 10.0.1;
* исправлена проверка обновлений при отсутствии `Content-Length`;
* исправлена clean/standalone-сборка FBShell;
* WTL включена в автоматический механизм проверки обновлений зависимостей;
* README существенно дополнен и проиллюстрирован;
* документирована политика поддержки Windows.

Поэтому 3.0.1 лучше всего характеризовать как релиз **обновления UI-фундамента, стабильности сборки и документации**.
