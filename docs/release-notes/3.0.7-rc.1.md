# FictionBook Editor Next 3.0.7 RC1

Первый кандидат на выпуск FictionBook Editor Next 3.0.7.

RC1 предназначен для расширенного тестирования перед стабильным выпуском. Он **не устанавливается автоматически поверх стабильной версии 3.0.6** и в первую очередь содержит исправления надёжности редактора, работы с иллюстрациями, пользовательскими скриптами и Windows 7, а также первые улучшения режима редактирования XML-кода.

## Главное в RC1

* Исправлена COM-ошибка при переходе из режима **«Тело» в «Код»** для книг с иллюстрациями.
* Переработано сохранение встроенных изображений и другого содержимого `<binary>`.
* Добавлен встроенный **диагностический журнал** для поиска причин сбоев и ошибок.
* Существенно улучшена диагностика ошибок пользовательских JavaScript-скриптов.
* Исправлена загрузка пользовательских скриптов portable-версии из путей с кириллицей.
* Добавлены первые настраиваемые цветовые схемы редактора XML-кода.
* Устранено подвисание проверки орфографии при редактировании больших разделов.
* Исправлена работа Batch-конвертеров на Windows 7.

## Режим «Тело» → «Код» и сохранение FB2

Исправлена одна из наиболее неприятных ошибок предыдущей версии — сбой при переходе в режим исходного XML-кода для книг, содержащих изображения.

Причина была связана с обработкой `<binary>` и особенностями MSXML6.

В RC1:

* исправлен вызов вспомогательного JavaScript-кода при переходе между режимами;
* исключено использование неподдерживаемого для данной операции `MSXML6 put_text`;
* переход из «Тела» в «Код» больше не должен приводить к COM-ошибке `0x80070057`;
* подготовлены дополнительные regression-тесты переключения между визуальным и исходным представлением документа.

Особенно рекомендуется проверить книги с большим количеством иллюстраций и несколько последовательных переходов между режимами.

## Сохранение изображений и `<binary>`

Переработана сериализация встроенных бинарных объектов FB2.

Теперь при сохранении:

* base64-содержимое `<binary>` записывается компактно;
* исключены дополнительные переводы строк, автоматически добавлявшиеся MSXML;
* преобразование выполняется через текстовый DOM-узел вместо `put_text` элемента;
* оптимизация выполняется **только при сохранении документа** и больше не вмешивается в переход к режиму «Код»;
* сохраняются допустимые дефисы и тире в `id` вновь добавляемых изображений.

Изменения особенно заметны на FB2 с большим числом или крупным объёмом встроенных изображений.

## Диагностический журнал

В FBE Next появился штатный диагностический журнал.

Включить его можно через:

**Сервис → Диагностическая трассировка…**

или переменной окружения:

`FBE_NEXT_TRACE`

Журнал сохраняется в:

`%LOCALAPPDATA%\FBE Next\fbe-trace.log`

Он предназначен прежде всего для разбора ошибок, которые трудно воспроизвести на другом компьютере.

В журнал записываются события, относящиеся к:

* запуску FBE;
* командам меню и панели инструментов;
* горячим клавишам;
* перемещению и восстановлению выделения;
* открытию и сохранению документов;
* созданию `.bak`;
* автосохранению и восстановлению;
* проверке FB2;
* запуску пользовательских скриптов;
* созданию XML DOM;
* COM/HRESULT-ошибкам.

Записи разделяются по категориям, в том числе:

`startup`, `command`, `selection`, `document`, `recovery`, `script`, `com`, `error`.

В заголовок журнала добавляются версия FBE и архитектура операционной системы.

При включённой диагностике программа обозначает этот режим в заголовке окна, а при следующем запуске предлагает при необходимости отключить трассировку.

Текст редактируемой книги в журнал не предназначен для записи.

## Ошибки пользовательских JavaScript-скриптов

Диагностика проблем при загрузке пользовательских `.js`-скриптов стала значительно информативнее.

Вместо малополезного общего сообщения FBE теперь может показать:

* тип ошибки;
* этап загрузки;
* имя скрипта;
* полный путь к файлу;
* строку и позицию ошибки;
* фрагмент исходного кода;
* указатель на проблемное место;
* исходное сообщение JScript;
* HRESULT.

Диагностические сведения можно скопировать в буфер обмена и приложить к issue.

Это должно заметно упростить поиск несовместимых, повреждённых или ошибочных пользовательских скриптов.

## Portable-версия и Unicode-пути

Исправлена работа пользовательских скриптов в portable-сборке, если путь к FBE содержит кириллицу.

Например, установка вида:

`D:\Программы\FictionBook Editor Next\`

больше не должна приводить к потере пользовательской папки Scripts или связанных настроек.

Исправления включают:

* отказ от формирования пути через фиксированный буфер `MAX_PATH`;
* корректную работу с Unicode-путями;
* сохранение исходного регистра пути к каталогу `Scripts`;
* дополнительную диагностику выбранного каталога скриптов и количества найденных файлов.

Рекомендуется проверить portable-версию также из каталогов с пробелами и длинными именами.

## Редактор XML-кода

В настройках FBE Next появился первый вариант управления оформлением XML-подсветки.

Для RC1 доступны три схемы:

* **классическая** — используется по умолчанию;
* **контрастная**;
* **тёмная**.

Выбранная схема сохраняется в настройках.

Подписи вариантов локализованы для runtime-локализаций, а также русской и украинской ресурсных DLL.

Это первая версия новой системы оформления режима «Код»; дальнейшее расширение набора тем появилось уже в следующих кандидатах 3.0.7.

## Неразрывный пробел

Исправлена настройка отображения неразрывного пробела.

Ранее символы, выбранные для визуального обозначения NBSP, могли превращаться в `?`.

В RC1:

* выбранный символ отображается корректно;
* изменение обозначения применяется к уже открытому документу;
* не требуется заново открывать книгу только для обновления отображения.

Сам символ U+00A0 в тексте FB2 при этом не заменяется — меняется только его отображение в редакторе.

## Проверка орфографии и производительность

Устранён источник заметного подвисания проверки орфографии на больших документах.

Ранее после небольшого изменения в конце длинного раздела механизм обновления подчёркиваний мог искать видимую область последовательным обходом большого количества абзацев документа.

Теперь:

* после локального изменения повторно проверяется прежде всего изменённый абзац;
* исключён лишний обход всего длинного раздела;
* обновление орфографических подчёркиваний должно происходить значительно быстрее.

Особенно полезно проверить длинные главы и книги с большим количеством абзацев.

## Windows 7 и Batch-конвертеры

Исправлена совместимость пакетных конвертеров с Windows 7 SP1.

Win7-вариант поставки теперь содержит отдельно собранные:

* `ExportDOCXBatch.exe`;
* `ExportEPUBBatch.exe`;
* `ImportEPUBBatch.exe`.

Они собираются с API-уровнем Windows 7.

В частности, `ExportEPUBBatch.exe` больше не должен требовать отсутствующую в Windows 7 функцию `CreateFile2`.

Дополнительно изменено поведение Batch-программ при запуске двойным щелчком:

вместо мгновенно появляющегося и исчезающего консольного окна выводится сообщение о том, что программу следует запускать из командной строки или PowerShell с необходимыми параметрами.

## Локализация интерфейса

Исправлен ряд проблем русской и украинской локализации:

* синхронизированы новые команды меню;
* исправлены повреждённые подписи и подсказки;
* добавлена локализация настроек диагностического журнала;
* локализован выбор цветовых схем режима «Код».

В частности, команда диагностической трассировки теперь корректно присутствует в меню **«Сервис»** при русском и украинском интерфейсе.

## Внутренние изменения

Для подготовки 3.0.7 RC1 также переработан release-конвейер.

* Добавлена поддержка тегов вида `vX.Y.Z-rc.N`.
* Release Candidate публикуется как **pre-release**.
* Публикация RC не изменяет манифест автоматического обновления стабильной версии.
* Улучшена проверка содержимого Modern- и Win7-пакетов.
* Release-проверки контролируют наличие именно Win7-вариантов необходимых бинарных компонентов.
* Оптимизирована сборка общих и Windows 7-зависимых компонентов.
* Расширены regression-тесты сохранения `<binary>`, portable-путей, переключения между режимами и формирования release-пакетов.

## Что особенно желательно проверить

Поскольку это первый Release Candidate 3.0.7, особенно полезны результаты тестирования следующих сценариев:

* переходы **«Тело» → «Код» → «Тело»**;
* FB2 с большим количеством изображений;
* сохранение и повторное открытие книг с `<binary>`;
* сохранение изображений с дефисами и тире в имени;
* работа проверки орфографии в очень длинных разделах;
* portable-сборка из пути с кириллицей, пробелами и длинными именами;
* загрузка собственных JavaScript-скриптов;
* диагностика намеренно повреждённого пользовательского скрипта;
* переключение классической, контрастной и тёмной XML-схем;
* изменение обозначения неразрывного пробела;
* Batch-конвертеры на Windows 7 SP1;
* экспорт и импорт EPUB на Windows 7;
* работа установщика и portable-сборки на Windows 10/11.

При возникновении воспроизводимой ошибки желательно включить диагностический журнал, повторить проблемное действие и приложить полученные сведения к issue.

## Что скачивать

Для обычных современных систем:

* `FictionBookEditorNext-3.0.7-win32-setup.exe` — установщик для Windows 8.1 / 10 / 11;
* `FictionBookEditorNext-3.0.7-win32-portable.zip` — portable-версия для Windows 8.1 / 10 / 11.

Для Windows 7 SP1:

* `FictionBookEditorNext-3.0.7-win7-win32-setup.exe` — установщик;
* `FictionBookEditorNext-3.0.7-win7-win32-portable.zip` — portable-версия.

RC1 является предварительным выпуском. Для повседневной работы без тестирования можно продолжать использовать стабильную 3.0.6.
