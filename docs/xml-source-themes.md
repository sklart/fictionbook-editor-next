# Темы редактора исходного XML

Подсветка режима «Код» отделяет распознавание синтаксиса Lexilla от
оформления. Лексер выдаёт стили `SCE_H_*`, а FBE сопоставляет их со
стабильными ролями `XmlSrcStyleToken`; номера стилей Lexilla не входят в
формат темы.

## Выбор и применение

Историческая светлая схема сохранена как отдельный встроенный вариант. В списке сначала идут встроенные варианты: `system-auto`, `fbe-light`,
`fbe-dark` и `fbe-historical`; затем встроенные файловые темы и пользовательские
темы. `system-auto` выбирает `fbe-light` или `fbe-dark` по настройке Windows и
безопасно возвращается к `fbe-light`, если её нельзя определить. Выбор и ручные
цветовые переопределения хранятся в `Settings.xml` по стабильным идентификаторам.

Все цвета применяются к основному Scintilla-редактору исходного XML. При
изменении системной темы Windows режим `system-auto` переоформляет открытый
редактор без перезапуска приложения.

## Формат `.fbetheme`

Файл темы — UTF-8 JSON с расширением `.fbetheme`. Поддерживается только
`formatVersion: 1`; прежние файлы `.json` намеренно не загружаются. При импорте
для вручную созданных русскоязычных файлов дополнительно принимается Windows-1251,
после чего копия в пользовательском каталоге записывается заново в UTF-8. Обязательны
строковые `id`, `name`, `type` (`light` или `dark`) и все 23 цвета в объекте
`colors`. Идентификатор содержит только строчные латинские буквы, цифры и
дефисы. Неизвестные поля игнорируются.

```json
{
  "formatVersion": 1,
  "id": "my-light",
  "name": "My light theme",
  "type": "light",
  "colors": {
    "editor.background": "#FFFFFF",
    "editor.foreground": "#202224",
    "editor.selection.background": "#0068BE",
    "editor.selection.foreground": "#FFFFFF"
  }
}
```

При последующем расширении приоритет оформления остаётся определённым: пользовательское правило конкретного тега, пользовательское правило токена, семантическая группа FB2, базовая XML-роль и основной цвет текста. Текущая версия применяет базовые роли; дополнительные уровни не записываются в .fbetheme.

Полный перечень ролей: `editor.background`, `editor.foreground`,
`editor.selection.background`, `editor.selection.foreground`,
`editor.currentLine.background`, `editor.caret`, `editor.lineNumber`,
`editor.lineNumber.active`, `editor.matchingTag.background`,
`editor.matchingTag.border`, а также `xml.text`, `xml.tag.name`,
`xml.tag.delimiter`, `xml.attribute.name`, `xml.attribute.value`,
`xml.namespace`, `xml.comment`, `xml.entity`, `xml.cdata`,
`xml.processingInstruction`, `xml.doctype`, `xml.error`, `xml.warning`.

## Пользовательские темы

В меню `…` рядом с выбором темы доступны импорт одной или нескольких `.fbetheme`, экспорт, «Сохранить
текущую тему как…» и удаление. Импорт проверяет размер, UTF-8 JSON, версию,
идентификатор и полный набор цветов; встроенную тему заменить нельзя. При
совпадении id создаётся отдельная пользовательская копия с уникальным id.
Ошибка одного файла при множественном импорте не отменяет остальные, а в
результате перечисляются пропущенные файлы. Новая тема появляется в этом же
окне настроек сразу после импорта. Удаление доступно только для пользовательских
файлов и не затрагивает встроенную поставку.

Пользовательские темы размещаются в `Themes` внутри того же каталога, что и
`Settings.xml`: обычно `%LOCALAPPDATA%\FBE Next\Themes`. Если Windows не
предоставляет каталог пользовательских данных, используется существующий
резервный каталог программы; таким образом, установленная и portable-сборки
следуют общему правилу хранения настроек FBE и не требуют записи в `Program Files`.
При экспорте в файл сохраняются также текущие ручные переопределения цветов. При экспорте режима `system-auto` в файл записывается фактически разрешённая FBE Light или FBE Dark палитра, без зависимости от темы Windows на другом компьютере.
«Сохранить тему как…» запрашивает название, создаёт уникальный id `user-theme`,
`user-theme-2` и т. д., записывает копию в пользовательский каталог и сразу
делает её выбранной.
Ручная смена цвета не изменяет файл встроенной темы: она сохраняется как
переопределение выбранной базовой темы в `Settings.xml`. В списке такая тема
помечается «— изменена». «Восстановить цвета схемы» удаляет только эти
переопределения; выбор другой темы и «Отмена» окна не сохраняют их.

## XML-комментарии

Lexilla распознаёт XML-комментарии и использует роль `xml.comment`, однако
ручной цикл с `fb2-xml-comments-smoke.fb2` подтвердил: модель документа FBE
удаляет или преобразует comment nodes после перехода через визуальный редактор
и сохранения FB2. Поэтому настройка цвета комментариев
и комментарий в предпросмотре намеренно скрыты. Полная поддержка возможна после
регрессионного цикла: открытие FB2 с комментариями, переключение режимов,
редактирование, сохранение и повторное открытие. Базовый XSD-фикстур `tools/tests/fb2-xml-comments-smoke.fb2` содержит комментарии в `description`, `body`, между `section`, между абзацами и после `body`; его проверяет `tools/tests/test-fb2-xml-comments.ps1`. Визуальный цикл намеренно не считается доказательством сохранности, пока не будет автоматизирован или пройден вручную для всех этапов.
