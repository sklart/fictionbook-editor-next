# Карточки скриптов: сверка перед миграцией

Состояние `runtime/Scripts` до вставки карточек проверено относительно каталога `FBE-Next-Script-Cards-b8312c48`.

| Проверка | Результат |
| --- | --- |
| Исходный commit каталога | `b8312c4842f8910890c2473771b0d7ba5f268cda` |
| Git tree `runtime/Scripts` в исходном commit | `64c413305ea8f953981f3aa1a2c79a1baff4086f` |
| Git tree `runtime/Scripts` перед миграцией | `64c413305ea8f953981f3aa1a2c79a1baff4086f` |
| Путей `.js` в каталоге и рабочей копии | 580 и 580; недостающих и лишних нет |
| Git diff по `runtime/Scripts` между исходным и текущим состояниями | Пустой |
| Совпадение SHA-256 сырых файлов рабочей копии с `source.sha256` каталога | 1 из 580 |

Последнее число не означает 579 изменений кода: большинство файлов в рабочей копии развёрнуты с CRLF согласно `.gitattributes`, а исходные SHA каталога относятся к каноническим Git-байтам с LF. Для первого проверенного файла `01_Регистр/01_В верхний регистр.js` SHA-256 Git blob точно совпал с SHA каталога, а локальный сырой SHA отличился. Мигратор должен отдельно проверять Git blob и записывать в карточку SHA-256 **локальных исходных байтов** по `sha256-exclude-fbe-card-v1`.

Каталог сообщает 504 скрипта с явным авторством, 36 с частичной атрибуцией и 40 без установленного автора. Эти состояния будут сохранены без автоматического назначения сопровождающего автором. Для динамических зависимостей и неоднозначных эффектов останется явный непроверенный статус. Массовая запись исходников ещё не начиналась: сначала требуется завершить нативное чтение карточек, проверить загрузчик и пробные файлы разных кодировок.

Профильный runtime подтвердил запуск CP1251-скрипта с кириллицей до и после вставки длинной ASCII-карточки. Для пользовательских скриптов, которые MSHTML загружает через `<script src>`, кодировка теперь передаётся из `Doc::RunScript`; отдельный загрузчик `script.cpp` использует тело скрипта для эвристики MLang. Нативный парсер и CLI сверяют SHA-256 без блока, проверяют размещение маркеров и схему зависимостей. Фактические файлы зависимостей проверяются отдельно при открытии карточки.

## Результат миграции

Мигратор `tools/migrate-script-cards.py` сверил контрольную сумму каталога с manifest, исходный Git tree `runtime/Scripts` и отсутствие локальных изменений. Перед записью он подготовил все 580 карточек и для каждой проверил, что удаление точного блока восстанавливает исходные байты JS. После записи профильная проверка подтвердила 580 актуальных `sourceRevision` и синхронизацию производного индекса `runtime/Scripts/script-cards.index.json`.

| Показатель | Количество |
| --- | ---: |
| Обработано скриптов | 580 |
| Несовпадений исходного Git tree и каталога | 0 |
| Явно установленное авторство | 504 |
| Частичная атрибуция | 36 |
| Автор не установлен | 40 |
| Версия не установлена | 41 |
| Проверяемых известных связанных файлов | 138 |
| Неразрешённых динамических зависимостей | 13 |
| Ошибок кодировки или превышения лимита карточки | 0 |
| Карточек с отметкой о необходимости содержательной проверки (`generated`) | 580 |

При миграции `dependenciesComplete` остаётся `false`: статический каталог не доказывает полноту списка ресурсов. Хеши связанных JS вычисляются без встроенной карточки, поэтому редактирование только её описания не создаёт ложное предупреждение у вызывающих скриптов. Для прочих ресурсов используется хеш фактических байтов. Неизвестные роли участников сохранены как `contributor` с исходным значением в `contribution`; частичная и отсутствующая атрибуция явно отмечены в каждой карточке.

Один исходный файл, `32_Маркеры сносок/52_Слить выделенные строки с маркерами номеров и текстами сносок.js`, содержит LF при общем правиле CRLF для скриптов. Для него добавлено точечное правило `text eol=lf` в `.gitattributes`; профильный тест проверяет, что после Git-нормализации и повторного checkout хеш кода каждой из 580 карточек остаётся актуальным.
