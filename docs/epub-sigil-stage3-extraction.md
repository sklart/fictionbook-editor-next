# EPUB: контролируемая распаковка

Windows Shell ZIP provider заменён потоковым извлечением через уже
используемые проектом статические libarchive и zlib. Последующая обработка
OPF, XHTML и навигации остаётся прежней. Никакой код Sigil не переносился:
изучен подход к непосредственной работе с содержимым EPUB в
[epub_utils.py](https://github.com/Sigil-Ebook/Sigil/blob/master/src/Resource_Files/plugin_launchers/python/epub_utils.py)
и отмеченная в [журнале Sigil](https://github.com/Sigil-Ebook/Sigil/blob/master/ChangeLog.txt)
защита от zip-slip. Зависимость проекта от Qt не добавлена.

Распаковщик проверяет завершение и каталог ZIP/ZIP64, сырые имена в обоих
заголовках, CRC и фактическую длину извлечённых файлов. Запрещаются пути за
пределами временного каталога, устройства Windows, потоки, повторяющиеся и
конфликтующие имена, ссылки, зашифрованные и специальные записи. Каталоги
открываются без перехода по reparse points и удерживаются во время записи.
Память на данные файла ограничена буфером 64 КиБ; действуют ограничения
100 000 записей, 8 ГиБ на файл, 32 ГиБ суммарно и резерв 256 МиБ свободного
места. Унаследованное ограничение путей Windows MAX_PATH сохраняется.

Имена UTF-8, CP437 и поле Unicode Path проверены тестами. ZIP-имя в CP1251
без признака кодировки неоднозначно: ни прежний Shell на проверенной машине,
ни новый механизм не нашли ресурс, на который ссылался тестовый OPF. Такой
файл не объявляется успешно импортированным. Реальное исполнение под Windows
7 SP1 данной проверкой не подтверждено; сборка нацелена на Windows 6.1.

## Сравнение до переключения

До удаления старого пути обе реализации запускались в одном тестовом DLL.
Полные FB2 после EPUB 2 и 3 с текстом, форматированием, внутренней ссылкой,
сноской, обратной ссылкой и изображением совпали; независимая проверка FB2
по XSD прошла. Четыре реальные книги из `01_valid_clean` (`wasteland`,
`trees`, `sous-le-vent`, `regime-anticancer-arabic`) дали побайтно
одинаковые FB2. Это выборка, а не проверка всего корпуса.

На одной синтетической книге с 12 000 абзацев и EPUB размером 93 146 байт
два последовательных замера полного импорта дали для Shell 35,232 и
35,859 с, для libarchive 35,831 и 35,480 с. Наблюдаемый пиковый рабочий
набор: соответственно 84 803 584 / 84 148 224 и 74 203 136 / 74 657 792
байт. Результирующие FB2 совпали по SHA-256. Это измерения одного компьютера,
а не универсальная оценка. Отдельный тест с 1 200 ресурсами прошёл.

`test-import-epub-secure-zip.py` проверяет ZIP64, кодировки, повреждения,
CRC, обход каталогов, конфликтующие имена, символьные ссылки и множество
ресурсов. Существующий `test-prerelease-epub-import.ps1` проверяет
обязательные ресурсы, ограничения путей и очистку при внедрённом reparse point.
