# Issue #43: стадия интерфейсных исправлений

Базовая серия исправлений опубликована в `master` до `74ebe486`; исправление стартового режима «Скрипты» — `be675e84`. Это отчёт о реализации и коротких проверках, **не акт приёмки**. Общая GUI/DPI-регрессия вместе с issues #44, #49 и #45 остаётся отложенной согласно ТЗ.

## Финальная корректировка авторазмера Settings (12.10.2026)

- Положение окна и признак ручного изменения размера сохраняются отдельно. Наличие старой геометрии без признака ручного размера оставляет автоматический подбор включённым. При каждом открытии в этом режиме размер рассчитывается по содержимому восьми страниц с ограничением рабочей областью монитора.
- `WM_ENTERSIZEMOVE` запоминает исходный размер; `WM_EXITSIZEMOVE` сравнивает его с итоговым с допуском 2 логических пикселя. Сам `WM_SIZING`, перемещение окна и возврат к исходному размеру не отключают авторазмер. При переходе на другой DPI учитывается изменение масштаба; реальное ручное изменение размера сохраняется.
- Профильный тест создаёт `TestData\Settings` до запуска, читает только `TestData\Settings\Settings.xml` и отклоняет сохранение рядом с `FBE.exe`. Он проверяет первое и повторное открытие, старую уменьшенную геометрию без нового признака, ручной размер, перемещение и возврат после растягивания.
- Короткая проверка на обновлённом бинарнике: инкрементальная сборка только проекта FBE Win32, `test-fbe-settings-dialog-runtime.ps1` и `git diff --check` — PASS. Полный Release gate, CI и реальная GUI/DPI-матрица остаются в общей приёмке #43, #44, #49 и #45.

| UI Layout Audit | Отсутствовал структурированный аудит. Добавлен сбор HWND, текста, языка, DPI, прямоугольников, возможных перекрытий и обрезания с измерением шрифта. Намеренно выведенные за viewport элементы больше не отмечаются как выход за монитор, если у родителя есть действующий диапазон прокрутки по нужной оси. |
