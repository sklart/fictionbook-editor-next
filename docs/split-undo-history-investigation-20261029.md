## Уведомления и Dirty Range

В `CFBEView` `IHTMLChangeSink::raw_Notify` вызывает `EditorChanged(RANGE_SINK)`, а `GetChangedNode` использует `GetAndClearDirtyRange` с собственным cookie. [Microsoft описывает](https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/platform-apis/aa703629%28v%3Dvs.85%29) регистрацию отдельного sink и cookie для соответствующего диапазона. Test-only проба регистрирует **второй** sink/cookie и очищает только его, не штатный cookie дерева. Одна книга и один процесс, восемь последовательных изменений скрипта; фиксируются DOM до/после, версия, число Notify сразу после скрипта, после обработки очереди до собственного `PostThreadMessage` и после дополнительного ожидания до 100 мс, HRESULT диапазона и `CurrentScope` концов.

| Изменения | Наблюдение в одном тесте |
|---|---|
| `nodeValue`, `innerHTML`, `appendChild`, `insertBefore`, `removeChild` | Сразу после скрипта счётчик не вырос; при обработке сообщений вырос на 1 для каждого. `GetAndClearDirtyRange=S_OK`; концы имеют scope P или DIV. Версия увеличилась |
| `id` | Notify не вырос к последнему снимку; версия 1696→1697. Оба scope пусты при `S_OK` |
| `href` | DOM изменился, Notify не вырос, версия 1697→1697; scope пусты при `S_OK` |
| Два изменения `title` подряд | DOM изменился, Notify не вырос, версия 1697→1697; scope пусты при `S_OK` |

При наличии готовых сообщений `MsgWaitForMultipleObjectsEx` может вернуться раньше 100 мс; это не гарантированное полное окно наблюдения. Срабатывание `EditorChanged` штатного sink, фактическая пространственная точность диапазона, идентичность удалённого узла, отдельные документы, повторения и полный возврат из внешнего Windows-сообщения не измерены. `S_OK` и пустой CurrentScope не доказывают отсутствие любых внутренних уведомлений. Значение до мутации получено отдельным снимком, а не из Notify; одного dirty range недостаточно считать полноценным обратимым журналом.

[Документация `CreateChangeLog`](https://learn.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/platform-apis/aa703624%28v%3Dvs.85%29) описывает forward/backward сведения как отдельную возможность; её фактическая доступность, покрытие атрибутов и пригодность для Undo здесь **NOT RUN**. Отложенные JS `oninput`/`onpropertychange` из предыдущей пробы также не повторены после полного внешнего цикла; результаты отдельного change sink не следует подменять результатами JS-событий. `CHANGE_NOTIFICATION_COMPLETENESS — INCONCLUSIVE`.

Первый прогон dirty-пробы зафиксировал первые шесть операций, затем завис из-за тестовой ссылки, ID которой отсутствовал после преобразования FB2. Завершён только собственный изолированный процесс; его частичный лог сохранён. Исправленная проба получила ссылку по DOM-положению и прошла все восемь шагов. Этот случай не классифицируется как авария редактора.
