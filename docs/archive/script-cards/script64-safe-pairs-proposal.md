# Предложение: безопасный разбор списка замен скрипта 64

Статус: реализовано отдельным этапом. Ниже сохранено исходное предложение;
[актуальное исправление и проверки](script64-literal-pairs-report.md).

## Воспроизводимая проблема

Фактический Run выполнен через штатный `Doc::RunScript` в FBE Next / MSHTML / JScript.
Список замен с тремя строками `a$`, `b\`, `c"` для выделения `abc` вызывает
«Незавершённая строковая константа». Текст остаётся `abc`: ошибка возникает при
формировании/исполнении объекта замен, до открытия группы отмены.

Отдельно прошли исходные символы `. + * ? ( ) [ ] ^ $ | /`, обратная косая черта
и двойная кавычка в левой части пары. Это не подтверждает поддержку тех же знаков
в правой части. Обычные пары `aA` и `bB` дали `ABc AB` из `abc ab`; одно стандартное
Ctrl+Z вернуло исходный текст. Пустое выделение и пустой/неверный список отклонены.

`eval(str)` исполняет код, составленный из содержимого буфера обмена.
Цепочка исправлений кавычек и косых черт уже не справляется с допустимыми символами.
Произвольное исполнение атакующего кода этими проверками **не доказано**;
проверка длины пары не является самостоятельным обоснованием безопасности eval.

## Предлагаемая отдельная правка

1. Нормализовать окончания строк, удалить обычные пробелы по прежнему правилу,
   игнорировать пустые строки. Каждая оставшаяся строка должна содержать ровно
   две кодовые единицы UTF-16, как в исходном JScript; расширение до Unicode-кодовых
   точек — отдельное решение о совместимости.
2. Прочитать два символа непосредственно в массив пар. Не строить JS-исходник,
   не вызывать eval/Function и не интерпретировать экранирование пользователя.
3. Для буквальной замены использовать `text.split(from).join(to)`, совместимый
   с JScript. Тогда знаки регулярных выражений и `$` в замене не имеют скрытого смысла.
4. Сохранить последовательное применение разных правил: результат первой замены
   участвует в следующих. До правки отдельно проверить повторные исходные символы:
   текущий объект оставляет последнее значение ключа; простой массив строк изменит
   эту семантику. Зафиксировать и проверить совместимое правило до реализации.
5. Сначала проверить весь список, затем менять документ. Обход DOM, выделение,
   авторство, интерфейс и контракт window.external оставить прежними.

## Проверки будущего исправления

Обычные пары, каскадные правила, повторные ключи, пустой список и выделение,
неверная длина строки; каждый метасимвол слева и справа отдельно и в одном списке;
кавычка, обратная косая черта, `$`, кириллица, границы текстовых узлов и TEXTAREA.
Проверить одну обычную отмену в книге и отдельно поведение многострочного поля.

Существующий стенд `tools/tests/test-script64-runtime.ps1` сохраняет исходный Run
без переписывания, запускает его в настоящем редакторе и оставляет отчёт о результатах.
MsgBox/alert перехватываются на границе теста, чтобы отказы не блокировали прогон.
Неуспех правой части со спецсимволами остаётся отрицательным результатом проверки,
а не заменяется успешным синтаксическим разбором.
