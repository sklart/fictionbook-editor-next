# Штатный recovery удаляет Redo при нормализации живого DOM

**Статус: CONFIRMED в изолированной нативной регрессии; исправление не вносилось.** Это самостоятельная проблема `SaveRecoveryNow`, воспроизводимая без команды Split и без выполнения исследовательского SplitPlan.

В обычном визуальном документе выполнить три отдельные правки, отменить две и вызвать сохранение recovery при существующих двух Redo. На fixture с тремя внутренними ссылками штатный recovery изменил живые `file:///.../main.html#id` на `#id`, а стек 1 Undo / 2 Redo стал 2 Undo / 0 Redo. Dirty и наблюдаемая каретка сохранились. Результат повторён в отдельных процессах; он не означает, что все вызовы recovery непременно уничтожают Redo.

Путь вызовов: `CMainFrame::SaveRecoveryNow` → `RecoveryService::Save` → `Doc::SaveRecoveryCopy` → `CreateDOMImp` с нормализацией визуального DOM → `CFBEView::NormalizeWithoutUndo`. Нормализация сначала пробуется на копии; при обнаружении изменения выполняется живой проход в нативной Undo-группе, включая `FixupLinks`. Дополнительная нативная серия отделяет создание XML от его записи: стек и живой DOM изменились уже при `CreateDOM`, а вызов `raw_save` для готового XML не изменил их дополнительно. На той же fixture `CreateDOM` с отключённой нормализацией ссылок и `CreateDOMForAnalysis` сохранили идентичности; это диагностические варианты, а не исправление.

Нормализация может очистить Redo и без ссылок: на fixture с соседними `emphasis` живой проход объединил два элемента в один. Это самостоятельное наблюдаемое структурное изменение, а не эквивалентность, скрытая сравнением. Для локальных адресов oracle допускает только `file:///.../main.html#id` ↔ `#id`; в контрольном случае объединения ожидаемая трансформация сверяется явно.

Результаты ограничены тестовыми fixture, синтетическими `WM_CHAR`, двумя повторами на комбинацию и наблюдаемым состоянием MSHTML. Они не доказывают безопасность отключения одной нормализации для произвольного FB2. Файловые ошибки, конкурентная запись и прекращение процесса не проверялись в штатном `SaveRecoveryNow` этим тестом.
