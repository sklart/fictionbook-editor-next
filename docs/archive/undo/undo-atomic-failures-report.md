# Остаточные замечания Undo: проверка отказов

Дата: 2026-10-16. Работа выполнена в отдельном worktree, ветка
`codex/undo-atomic-failures`. База ТЗ — `9de9dc69`; текущий `master` при
создании ветки — `5862d7d340011bb8b14a49177c6e31c130b9ae6d`. Между ними
изменений `FBEview.cpp` и `ImageDocumentInserter.cpp` нет.

## Изменения

- Binary Undo удерживает исходный узел, его положение, данные и идентификатор.
  До изменения создаются ресурсы компенсации и снимок списков обложек.
  При отказе восстановления кэшей, `Close` или `Add` возвращаются исходный
  binary и значения/варианты обложек. Направление операции меняется только
  после завершения; обратная операция незавершённого шага не регистрируется.
- HTML Restore заранее готовит замену и удерживает исходные узлы. Ошибка
  удаления/вставки, закрытия записи или регистрации Undo возвращает исходные
  узлы, выделение и состояние сохранения. Для компенсации уже выполненного
  дочернего шага сохраняются фактические узлы, а не только HTML-клоны.
- Команды редактора Undo/Redo удерживают обе истории для частных единиц FBE.
  После отказа они восстанавливаются только при совпадении состояния
  документа. Сравниваются HTML, поля формы, ссылки обложек и binary-данные.
  Не учитывается только способ сериализации флага `OPTION selected`:
  MSHTML материализует выбор по умолчанию при перестроении списка; выбранное
  значение `SELECT` проверяется отдельно.
- Нормализация возвращает `HRESULT`, не поглощает COM-ошибку обхода и
  предварительно проверяет преобразование копии затронутого контейнера.
  При обычном Drop живое изменение остаётся нативным: это сохраняет позиции
  MSHTML, от которых зависит Undo самого переноса. При ошибке второго
  контейнера или живого прохода отменяется весь Drop, включая нормализацию
  первого контейнера. В заблокированной транзакции HTML-вставки используется
  существующая DOM Undo-единица.
- Для отката нативной транзакции используется штатный `UndoTo`. Удаляется
  только полученная обратная запись этой транзакции; прежние единицы Undo
  остаются в менеджере, прежние Redo удерживаются и возвращаются в исходном
  порядке. Снимок для Drop готовится при настоящем начале переноса, а не при
  каждом обычном нажатии мыши.

Причина отдельной защиты истории: стандартный OLE-менеджер после ошибочного
`Do` компенсирует выполненные шаги и очищает истории. См.
[IOleUndoManager::UndoTo](https://learn.microsoft.com/en-us/windows/win32/api/ocidl/nf-ocidl-ioleundomanager-undoto)
и [IOleUndoManager::DiscardFrom](https://learn.microsoft.com/en-us/windows/win32/api/ocidl/nf-ocidl-ioleundomanager-discardfrom).
Защита команд относится к маршруту редактора; прямые вызовы менеджера внешним
COM-клиентом сохраняют стандартный контракт OLE.

Публичный IDL/COM-контракт, инструментальная цепочка, зависимости и минимальная
версия Windows не изменены. Дополнительные копия и проход ограничены областью
нормализации; производительность на больших книгах отдельно не измерялась.

`undo-atomic-failures` проверяет:

- отказы `RebuildImagesInfo`, `FillCoverList`, закрытия записи и `Add` при
  Undo и Redo, включая реальные исключения JScript через IDispatch после
  изменения кэша;
- ошибки после удаления и вставки HTML, при `Close` и `Add`;
- исходный полный HTML книги, все значения INPUT/SELECT и варианты OPTION,
  идентификаторы/типы binary, каждый байт `base64data` и ссылки изображений;
- идентичность и порядок COM-единиц обеих историй, закрытие групп, сохранение
  выделения, dirty и recovery/savepoint; повтор команды после отказа;
- работоспособность двух предшествующих нативных изменений после Undo/Redo
  обоих импортов;
- ошибки каждого этапа нормализации на копии, после живого изменения и при
  завершении транзакции;
- Validate, Save → Reopen, точное совпадение полного XML, данных binary и
  ссылок после повторного открытия.

воспроизведены на исходном FBE.exe до изменения кода и на проверенном новом
FBE.exe после изменения. Их исправление не включено в эту работу.

| plain-middle | FAIL: Undo, dirty/recovery | FAIL: Undo, dirty/recovery; validation/save PASS |

Использован `test-fbe-html-paste-runtime.ps1 -Cases <сценарий>` с отдельной
portable-копией FBE.exe для каждого варианта сборки. Журналы
`undo-baseline-*.log` и `undo-current-*.log` сохранены вместе с отчётами.

## NOT RUN и границы доказательства

- Windows 7, FBE 2.8.5 и пользовательская матрица реальных книг.
- Повторный настоящий перенос мышью: этот этап проверяет COM-отказы и
  контролируемый Drop, а не подменяет прежнюю отдельную ручную проверку.
- Полный `verify-release.ps1`, длительные E2E, все скрипты и стресс — по ТЗ.
- Одновременный постоянный отказ самого объекта документа или менеджера во
  время компенсации. Проверки вводят один отказ за операцию; при невозможности
  компенсации возвращается ошибка, а не объявляется успешное восстановление.
