# HTML Paste Undo: internal-history и plain-middle

База: `dafefd1cd239cedd885c68c88fb0e920e7e36561`, ветка `codex/html-paste-history`.

## Установленные причины

1. **Исходные FAIL и маршрутизация теста.** Оба сценария воспроизведены исходным runner без изменения критериев. В скрытом batch-окне `CContainerWnd::GetActiveWnd()` не находит видимых дочерних окон и возвращает Source. Фокус при этом находится в Body. Команда frame обходила `CFBEView::OnUndo` и отправляла нативный `WM_UNDO` прямо MSHTML: custom `PasteDomUndoUnit` оставалась на стеке. Диагностика фиксировала отсутствие вызова `PasteDomUndoUnit::Do`, неизменную вершину Paste и `IsChild(active, focus)=0`. В тесте команды теперь доставляются в message map реального Body. Условия сравнения HTML/dirty/recovery сохранены и дополнены проверками точных координат выделения, идентичности прежних Undo-объектов и закрытия групп.
2. **Нативная история и DOM.** После исправления доставки команд исходный `internal-history` сохранял HTML предыдущей правки, но не точную каретку. Дополнительная вставка внутрь ранее изменённого абзаца выявила потерю исходного DOM-узла и нативных ссылок Undo. Обычная вставка меняла живые узлы, а `PasteDomUndoUnit` восстанавливала клоны изменённого диапазона `prefix/suffix`; `targetedSnapshot` лишь ограничивал предварительное клонирование. Простое добавление `RetainOriginalChildren()` здесь сохраняло бы уже изменённые узлы. Даже отсоединение оригинала с последующим возвратом сохраняет COM-объект, но перемещает внутренние markup pointers MSHTML. Поэтому обычная HTML-вставка теперь использует нативные записи вставки и нормализации внутри одной существующей родительской группы Undo. `PasteDomUndoUnit`, журнал компенсации и удержание оригиналов остаются для остальных потребителей, включая изображения и заблокированную нормализацию.
3. **plain-middle.** `PlainTextToHtml()` корректно формировал три абзаца, включая пустой; после самой вставки исходные части `Befo` / `re` и соседняя секция сохранялись. Исходный ошибочный путь Undo отменял только нативное заполнение пустого P (`&nbsp;`), оставляя вставку. При правильной доставке snapshot-восстановление HTML работало, но сохранённый живой TextRange уже смещался при замене узлов. Общая нативная группа и сохранённые числовые позиции обоих концов выделения устраняют эти проблемы. Конвертер и семантика Paste Text не менялись: наличие HTML в буфере игнорируется.
4. **OnRealPaste.** Отменённый браузерный paste-event создаёт пустую нативную запись перед отложенным `WM_COMMAND`. Без обработки первый Undo отменяет вставку, второй — пустое событие, оставляя Prior edit. Снимок истории и полного состояния документа перед событием позволяет распознать ровно одну новую нативную запись. Она отменяется до вставки; неизменность документа проверяется повторно, удаляется только её отдельный inverse на Redo, восстанавливаются прежние записи и savepoints. При неожиданном состоянии вставка возвращает ошибку. Предыдущий стек Undo не очищается.
5. **ID при разделении P.** Дополнительная проба внутри абзаца с ID обнаружила, что `pasteHTML` копирует ID на новый хвост. Теперь дубликат удаляется только из новых соседних P до прежнего следующего узла, в той же нативной группе. Исходный узел, ID и ссылки на него сохраняются; Validate и Save → Reopen проверяются и для этого случая.

Команды runtime-проверок: `test-fbe-html-paste-runtime.ps1 -Cases internal-history,plain-middle -KeepArtifacts`, дополнительный `internal-history-middle`, перечисленная выше регрессия и те же внутренние сценарии с `-RealPaste`. `-RealPaste` вызывает MSHTML Paste, требует события и отложенной команды; это проверка настоящего обработчика OnRealPaste, а не физического нажатия клавиш. Plain Text проверяется отдельно через свою команду при одновременном наличии HTML в буфере.

Для успешных сценариев проверяются полный HTML до/после Undo/Redo, точные оба конца выделения, dirty/recovery, возвращение к чистому savepoint, закрытые OLE-группы, Validate и равенство полного сериализованного FB2 после Save → Reopen. Дополнительный сценарий требует идентичности исходного P после Undo; прежние Undo-объекты сравниваются по COM-ссылкам.

## Среда и границы результата

Итоговая сборка выполняется в отдельном checkout `dafefd1c` с пятью файлами этого исправления. Посторонние параллельные изменения диагностики в основном каталоге не включены. Для сборки используются уже собранные pinned vendor-библиотеки и исходные vendor-заголовки; obj, generated API и executable изолированы.

До итоговой сборки выполнялись диагностические инкрементальные сборки и пробы; утверждение о единственной сборке за всю диагностику было бы неверным. В промежуточных пробах исправлены ошибки компиляции и аварийное сравнение NULL BSTR в новой проверке ID; источник исключения подтверждён отладчиком, затем исправлена явным преобразованием отсутствующего ID в пустую строку. Одна сборка в общем каталоге также пересеклась с параллельными изменениями диагностики и её результат не принимается как итоговый.

Один повторный запуск остановился до создания TSV; ранее наблюдался скрытый диалог сохранения настроек изолированного экземпляра. Это отмечено как сбой запуска среды, не PASS/FAIL Undo. Для финального контура используются исходные полные настройки тестового экземпляра. В atomic runner заменяется только seed Settings.xml; критерии и сценарий остаются исходными.

Артефакты диагностики, сборки, TSV и сохранённые FB2: `out/tests/html-paste-history/` (генерируемый, не коммитится). Публичные COM/JavaScript API, runtime/main.js, pinned vendor-версии и dependency DLL не изменялись. Совместимость Windows 7 не подтверждается запуском на современном host.
