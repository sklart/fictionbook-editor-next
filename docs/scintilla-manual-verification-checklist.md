# Инструкция по ручному тестированию режима «Код»

Цель: подтвердить, что новые функции Source editor работают в обычном FBE Next и не портят
содержимое FB2. Автоматические smoke/release-проверки это не заменяют.

## Подготовка

1. Используйте свежий `out\Release\FBE.exe`.
2. Создайте тестовый файл:

   ```powershell
   .\tools\tests\new-fb2-memory-fixture.ps1 -SizeMiB 1 -OutputPath .\tmp\manual-source.fb2
   ```

3. Откройте `manual-source.fb2` в FBE и переключитесь в режим «Код».
4. Для проверки большой книги дополнительно создайте fixture 20 MiB. Не используйте реальные
   книги в отчёте и не добавляйте generated fixture в Git.

## 1. Невидимые специальные символы

1. В режиме «Код» вставьте в абзац по одному символу: NBSP, NNBSP, SHY, ZWSP, ZWNJ, ZWJ,
   WORD JOINER и BOM.
2. Откройте **Настройки FBE Next → Source code**.
3. Выключите `Show invisible characters`, сохраните настройки и убедитесь, что вместо текста
   меток показываются сами символы.
4. Включите опцию. Убедитесь, что видны понятные метки `NBSP`, `SHY`, `ZWSP`, `ZWNJ`, `ZWJ`,
   `NNBSP`, `WJ`, `BOM`.
5. Для каждого символа проверьте: Copy/Paste, Find, Replace, Save, Undo, Redo.
6. Закройте FBE, откройте тот же файл снова и проверьте, что настройка сохранилась, а символы
   не изменились.

Ожидаемый результат: меняется только отрисовка. Поиск, замена, буфер обмена и UTF-8 содержимое
FB2 остаются корректными.

## 2. XML diagnostics

Для каждого случая внесите одну ошибку и нажмите **Файл → Проверить**:

1. Удалите `>` в начале документа.
2. Удалите закрывающий тег у абзаца в середине книги.
3. В 20 MiB fixture внесите ошибку ближе к концу.
4. Создайте ошибку с кириллицей в окружающем тексте.

После каждого случая проверьте:

- FBE открывает режим «Код»;
- EOL annotation находится у фактической строки ошибки;
- длинный текст annotation не перекрывает содержимое критически;
- после исправления текста annotation исчезает;
- повторная Validate показывает новую первую ошибку;
- успешная Validate очищает annotation;
- переход «Код → Тело → Код» не оставляет устаревшую annotation.

Ожидаемый результат: отображается только первая SAX/schema ошибка. Это штатно: текущий validator
прекращает проход на первом fatal callback.

## 3. XML autocomplete prototype

В пустом месте Source по очереди введите:

```xml
<
<section затем нажмите Space
<image xlink:
<a l:
```

Проверьте, что:

- после `<` предлагаются FB2-элементы;
- после `<section ` предлагается `id=`;
- после `<image xlink:` и `<a l:` предлагается `href=`;
- в обычном тексте `<p>обычный текст` подсказки не появляются;
- предложения не содержат слов художественного текста.

Autocomplete является prototype: он пока не подставляет существующие IDs после `#`.

## 4. Folding и Source chrome

На fixture с вложенными `section` проверьте click, Shift+click, Ctrl+click и Ctrl+Shift+click
на fold margin. Повторите при включённом и выключенном переносе строк.

Проверьте, что не ломаются:

- номера строк;
- fold margin;
- отображение длинного title;
- выделение и caret;
- подсветка парных XML-тегов.

Fold display text с `…` намеренно не включён и не является дефектом.

## 5. DPI и темы

Для каждого масштаба **100%, 125%, 150%, 200%** выполните базовую проверку режима «Код» в темах
**Light**, **Dark** и **High Contrast**. После смены DPI полностью перезапустите FBE.

В каждом сочетании проверьте:

- читаемость line numbers, текста и autocomplete;
- видимость caret и selection;
- matching-tag indicators;
- EOL annotation;
- special-character representations;
- fold margin без обрезания и цветовых артефактов.

DirectWrite и layout threads не проверяются: они отклонены и не включены.
