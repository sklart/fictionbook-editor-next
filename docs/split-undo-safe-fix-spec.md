# ТЗ: безопасное исправление Split/Undo в MSHTML

## Проблема и границы

После Split секции первый Undo восстанавливает текст исходной секции, но не удаляет второй фрагмент; оба фрагмента могут иметь один ID. Последующие Undo не восстанавливают исходный DOM, поскольку доступный стек уже исчерпан. Это дефект целостности документа. Доказательства и история отклонённого прототипа: [split-undo-closure-decision.md](split-undo-closure-decision.md), [архивный MSHTML probe](archive/undo/split-undo-mshtml-probe.md).

Задача — исследовать безопасное восстановление исходного DOM и истории без потери данных. Начинать реализацию до отдельного решения владельца не требуется. Не считать раздельные нативные Undo units дефектом сами по себе; сохранение дублированного раздела и ID после исчерпания истории недопустимо.

## Исследование

1. На фиксированных чистых сборках зафиксировать DOM, ID, ссылки, каретку, dirty/savepoint и содержимое Undo/Redo до Split, после Split и каждого шага отмены/повтора.
2. Установить, как MSHTML/OLE учитывает очистку исходного контейнера, вставку соседнего узла, перенос ID и завершение `MarkupUndoUnitScope`. Проверить `IOleUndoManager` и взаимодействие native units с последующими изменениями.
3. Сопоставить кандидаты с историческими неудачными вариантами и измерить сохранение предыдущей истории. Не использовать прежний custom-unit prototype, очищавший Redo последующего ввода.
4. До реализации представить варианты, ограничения, оценку влияния на другие команды и план отката. Глобальный слой Undo/Redo допустим только в отдельной согласованной задаче с самостоятельными границами.

## Требуемое поведение

- Текст, порядок, форматирование, заголовки, ID, обратные ссылки и содержимое обоих фрагментов сохранены; отсутствие дублированных ID проверяется после каждого завершённого состояния.
- Штатный Undo восстанавливает корректный исходный DOM и dirty/savepoint; Redo восстанавливает результат Split. Предшествующие операции остаются доступными.
- Последовательность `предыдущее редактирование → Split → ввод X → Undo X → Undo Split → Redo Split → Redo X` сохраняет оба стека, текст и каретку. Аналогично проверить отказ после первой мутации.
- Нельзя отключать проверки, подменять фикстуру или ослаблять `split-section-middle` для получения PASS. Временные промежуточные состояния не должны приводить к потере содержимого и неверной сериализации.

## Проверка кандидата

Обязательны RED/GREEN на реальном MSHTML/OLE; полный `test-fbe-split-container-production.ps1` с сохранением, XSD и reopen; тесты границ, выделения, stanza, форматирования, нескольких абзацев, существующего заголовка, ID/ссылок, предыдущей истории и инъекций отказа. Выполнить затронутую строгую Release Win32 сборку v143/14.44, стандартный `verify-release.ps1` и перед релизной приёмкой `-FullValidation`. Если безопасный вариант не найден, оставить BLOCKED с артефактами и не считать строгий gate пройденным.
