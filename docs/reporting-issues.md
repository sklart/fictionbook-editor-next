# Как сообщить об ошибке, падении или зависании

> Тип: Действующая инструкция. Документационная база: FBE Next 3.0.9, `master` / `1ad7c507d1ed`; сверка 19 октября 2026 года.

## Что приложить в первую очередь

Укажите версию и build SHA, Windows и её разрядность, installed/portable, активный режим редактора, точную последовательность действий и ожидаемый результат. Для визуального дефекта добавьте масштаб DPI, тему и скриншот; для скрипта — имя, редакцию и параметры; для преобразования — конкретный модуль и команду batch, если она использовалась.

Создайте отчёт в [GitHub Issues](https://github.com/sklart/fictionbook-editor-next/issues). Минимальная книга-пример полезнее полного конфиденциального документа. Не публикуйте текст книги, дамп или личные пути только потому, что файл назван «диагностикой».

## Диагностический ZIP

Откройте «Справка → Диагностика FBE Next…». Выберите нужный сеанс, проверьте состав и текстовый предпросмотр, исключите ненужные необязательные компоненты и сохраните пакет. Укажите в issue, когда произошло событие и какой сеанс выбран.

Подготовка выполняется в фоне. Экспорт использует подготовленный неизменяемый снимок, а не повторное чтение изменяющихся файлов. Если компонент пропущен или отклонён, сообщите причину из manifest; не пытайтесь вручную подменять его «похожим» файлом другой сессии.

Расширенная трассировка не нужна для каждого базового пакета. Для адресного воспроизведения включите её в окне диагностики и перезапустите FBE. Для одного запуска из каталога программы:

```powershell
$env:FBE_NEXT_TRACE = "1"
.\FBE.exe
Remove-Item Env:FBE_NEXT_TRACE
```

Переменная окружения имеет приоритет. Не оставляйте её включённой случайно после диагностики.

## Где лежат файлы

Installed: `%LOCALAPPDATA%\FBE Next\Diagnostics\`. Portable: `<каталог FBE>\Data\Diagnostics\` либо соответствующий `DataPath`. Для installed предусмотрен резерв `%TEMP%\FBE Next Diagnostics\`; portable не должен незаметно уходить в пользовательский профиль.

Подробные имена файлов, состав пакета, правила session_id и очистки описаны в [технической справке](reference/diagnostics.md).

## Падение

В `Diagnostics\Crashes` сохраняются исходные TXT и DMP. В стандартный ZIP входит проверенная техническая проекция текстового отчёта, **не исходный дамп**. DMP может содержать текст книги, пути и другие личные данные; передавайте его отдельно только осознанно и по запросу. Для анализа нужны символы соответствующей сборки.

Просмотренный неизменённый отчёт не должен вызывать повторное предупреждение. Отметка просмотра не равна удалению исходного TXT/DMP. Для повреждённого отчёта предусмотрена отдельная операция отметки просмотра; защита экспортируемого пакета при этом не отключается.

## Зависание

Запишите длительность, реакцию UI, последнюю команду и помогло ли завершение через Диспетчер задач. Текущая реализация уже содержит **watchdog**: он контролирует heartbeat после готовности UI и записывает эпизоды в `Diagnostics\Hangs`. Это не доказательство конкретной причины зависания.

Длительная синхронная операция тоже может выглядеть как неотзывчивость. Отсутствие hang-файла не доказывает отсутствие проблемы: важны этап запуска и фактическое состояние монитора. Его работа и последний код ошибки показываются в окне диагностики. Дампы зависания автоматически не создаются.

## Очистка

Очистка журналов, аварийных отчётов и зависаний — разные операции. Просмотрите рассчитанный список/объём и подтвердите удаление отдельным повторным действием. Не удаляйте вручную единственные свидетельства ещё не исследованного сбоя.

## Шаблон сообщения

```text
Версия и build SHA:
Windows / разрядность / DPI / тема:
Installed или portable:
Режим: Тело / Описание / Код:
Модуль или скрипт, если применимо:
Шаги:
Ожидалось:
Получено:
Повторяемость и минимальный пример:
Время события и выбранный диагностический сеанс:
Приложенные файлы, проверенные на конфиденциальность:
```

Отчёт о качестве книги, лог стороннего конвертера и стандартный диагностический ZIP имеют разное содержимое. Проверяйте каждый файл перед публикацией.
