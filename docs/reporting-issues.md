# Как сообщить об ошибке в FictionBook Editor Next

Если FictionBook Editor Next работает неправильно, завершается аварийно,
зависает или не запускается, пожалуйста, оформите сообщение так, чтобы проблему
можно было воспроизвести и исправить, а не только предположить её причину.

## Где создать отчёт

Предпочтительное место — [GitHub Issues проекта](https://github.com/sklart/fictionbook-editor-next/issues).
В заголовке коротко сформулируйте проблему, например:

- `Падение при открытии FB2 с PNG-обложкой`;
- `FBE Next зависает при запуске после обновления`;
- `ExportEPUB создаёт EPUB с некорректными сносками`.

[Группа Fiction Book Editor](https://groups.google.com/g/fiction-book-editor)
подходит для обсуждения, вопросов по установке и обратной связи. Перед новым
сообщением полезно поискать уже известную проблему: возможно, для неё есть
обходной путь или исправление в более новом релизе.

## Что обязательно указать

Укажите в отчёте:

1. Версию FictionBook Editor Next из окна «Справка → О программе».
2. Тип сборки: обычный установщик, portable-архив, Win7-сборка или сборка из
   исходников.
3. Версию и разрядность Windows, например `Windows 10 x64 22H2` либо
   `Windows 7 SP1 x86`.
4. Способ установки: установщик или portable; включались ли ассоциация `.fb2`,
   свойства/миниатюры Проводника и контекстная команда проверки; происходило ли
   обновление поверх предыдущей версии.
5. Точные шаги для повторения. Например:

   1. Запустил FictionBook Editor Next.
   2. Открыл `book.fb2`.
   3. Перешёл в режим «Код».
   4. Нажал «Проверить FB2».
   5. Программа закрылась без сообщения.

6. Ожидаемый результат и фактический результат.
7. Повторяемость: всегда, иногда, только один раз, зависит от файла или от
   определённого действия.
8. Скриншот окна ошибки или её точный текст.

Если проблема связана с книгой, приложите исходный `.fb2`, `.epub`, `.docx` или
другой файл, если его можно передавать. Если книгу нельзя публиковать из-за
авторских прав или личных данных, подготовьте минимальный пример: удалите
основной текст, но сохраните структуру, изображения, сноски, таблицы или другой
фрагмент, на котором ошибка всё ещё повторяется.

## Диагностический пакет

Откройте «Сервис → Диагностика FBE Next…». Окно показывает текущий режим,
источник включения трассировки, ошибку записи и расположение диагностических файлов.
Расширенный режим также отмечен в заголовке главного окна; повторных модальных
предупреждений при запуске нет.

1. Выберите нужный сеанс. Звёздочка отмечает сеансы с аварийным отчётом;
   последний такой сеанс предлагается первым. «Неизвестно» означает, что
   штатное завершение не зарегистрировано, и само по себе не доказывает аварию.
2. Нажмите «Предпросмотр / обновить», проверьте список, размеры и содержимое
   файлов. Двойной щелчок исключает или возвращает необязательный компонент;
   состав и проверенный снимок при этом пересоздаются.
3. Проверьте причины пропуска компонентов. При ошибке проверки обязательных
   данных сохранение запрещено. Старые журналы без идентификатора сеанса
   обозначаются отдельно: PID и время дают только приблизительное соответствие,
   а произвольный текст таких журналов не получает автоматического допуска в ZIP.
4. Нажмите «Сохранить пакет» и выберите **новое** имя ZIP. Сохраняются именно
   просмотренные байты: последующие записи работающей программы в него не попадут.
5. Приложите полученный ZIP к сообщению об ошибке. Отправки по сети программа
   не выполняет. Передача исходной книги — отдельное действие пользователя.

Пакет доступен и без расширенной трассировки: он включает версию, идентификатор
сборки, Windows, тип установки, сведения о DLL, доступные ошибки и подходящий
технический crash-отчёт. Отсутствующий журнал явно отмечается в пакете.

В архиве сохраняются текстовый `package-manifest.txt` и структурированный
`manifest.json` версии 2: выбранный `session_id`, время, исход завершения,
перечень файлов с размерами, пропуски и результат проверки. Данные окружения
сохраняются при старте соответствующего сеанса; окружение нынешнего запуска
не подставляется вместо отсутствующего исторического снимка.

### Статистика операций и режим редактора

`operation-statistics.txt` содержит счётчики загрузки, сохранения, проверки,
выполнения сценария и переключения режима: started, completed, failed, active,
суммарную, последнюю и максимальную длительность в миллисекундах. Completed
учитывает все завершения; failed — их неуспешное подмножество. Отдельно указаны
последняя завершённая операция и самая недавно начатая из ещё выполняющихся.
Длительность включает ожидание диалогов и вызовов COM, а не только работу CPU.
Для сценария успешность означает успешный HRESULT вызова apiRunCmd.

`active-editor-mode` принимает только unknown, body, description или source.
Он также находится в текущем `runtime-state.txt`. Счётчики работают без trace,
не содержат имён книг, путей или текстов сценариев. При заполнении 32 мест
активных операций новые измерения пропускаются с увеличением stats-dropped.

Текущий снимок помечен selected-current-session-at-preview. При штатном выходе
итог сохраняется в метаданные своего сеанса с пометкой
selected-session-at-shutdown. Если у прошлого сеанса такого итога нет, пакет
указывает historical-session-unavailable; данные текущего запуска вместо него
не подставляются. При аварийном завершении финальный итог может отсутствовать.
Это измерение операций, диагностика зависаний остаётся отдельным этапом.

### Расположение файлов

- Установленная версия: `%LOCALAPPDATA%\FBE Next\Diagnostics\`.
- Portable: `<каталог FBE>\Data\Diagnostics\`; если `portable.ini` задаёт
  другой `DataPath`, используется соответствующий каталог данных этой копии.
- Резерв установленной версии при недоступности основного каталога:
  `%TEMP%\FBE Next Diagnostics\`. Portable не переходит в профиль пользователя.

Сеанс имеет файл `fbe-session-<session_id>.txt`. Расширенный журнал:
`fbe-trace-YYYYMMDD-HHMMSS-mmm-pidNNN.log`; сегменты `-partN.log` принадлежат
тому же сеансу. Ошибки без расширенной трассировки записываются в ограниченный
`fbe-events-<session_id>.log`. Новые плагины используют backend приложения;
в самостоятельном процессе сохраняется ограниченный `fbe-diagnostic.log`
с явным `session_id=unavailable`, который не примешивается к сеансам FBE.

Очистка старых журналов требует повторного нажатия после показа количества
файлов и размера. Текущий сеанс, работающие процессы и имеющиеся аварийные
свидетельства защищены. Частичные ошибки удаления показываются пользователю.

### Включение расширенной трассировки

В окне диагностики нажмите «Вкл./выкл. трассировку» и перезапустите программу.
Для одного запуска можно использовать PowerShell:

```powershell
$env:FBE_NEXT_TRACE = "1"
.\FBE.exe
Remove-Item Env:FBE_NEXT_TRACE
```

Переменная окружения включает трассировку независимо от сохранённой настройки;
для её отключения нужно также убрать `FBE_NEXT_TRACE` из окружения запуска.
В обычном режиме подробная трассировка постоянно не записывается.
Свободный текст сообщений заменяется явной отметкой `details=omitted`;
сохраняются коды событий, источник, время и разрешённые числовые поля ошибок и технические перечисления.
При экспорте проверяются схема данных и конечные байты, а не только наличие
подозрительных слов или замена известных префиксов путей.

## Если программа аварийно завершилась

Подкаталог `Diagnostics\Crashes\` содержит пары:

```text
FBENext-crash-YYYYMMDD-HHMMSS-mmm-pidNNN.txt
FBENext-crash-YYYYMMDD-HHMMSS-mmm-pidNNN.dmp
```

После следующего запуска отметка в заголовке предлагает открыть диагностику.
Crash-отчёт сопоставляется прежде всего по `session_id`; совпадения одного PID
недостаточно. В стандартный ZIP входит только проверенная техническая проекция
текстового отчёта; исходный полный `.txt` остаётся доступен отдельно.

**Дамп `.dmp` может содержать текст книги, пути, настройки и другие личные
данные. Он не включается в стандартный пакет.** Передавайте его отдельно только
после осознанной проверки условий передачи, по запросу разработчика. Для разбора
дампа могут понадобиться debug-символы именно той сборки, в которой произошла авария.

Если программа зависла, укажите длительность, реакцию на мышь и клавиатуру и
помогает ли закрытие через Диспетчер задач. Постоянный монитор зависаний не включён.

## Ошибки открытия, сохранения и конвертации

Приложите исходный файл, ошибочно созданный результат, скриншот, выбранные
настройки импорта/экспорта и crash-отчёт, если программа завершилась. Для
плагинов обязательно назовите модуль: `ExportDOCX`, `ExportEPUB`, `ImportEPUB`,
`ExportHTML` либо batch-конвертер.

Если применялся batch-режим, приложите точную команду и его журнал. Например:

```text
ImportEPUBBatch.exe "input.epub" "output.fb2"
ExportEPUBBatch.exe "input.fb2" "output.epub"
```

## Ошибки Проводника Windows

Для проблем со свойствами `.fb2`, миниатюрами, значками или контекстным меню
укажите, включалась ли системная интеграция при установке, менялось ли
приложение по умолчанию для `.fb2`, наблюдается ли проблема только в Проводнике
и помогает ли перезапуск Проводника или Windows. Приложите скриншот, пример
FB2 и версию Windows.

## Если crash-файлы не появились

Откройте Монитор стабильности:

1. Нажмите `Win + R`.
2. Введите `perfmon /rel`.
3. Найдите день и время сбоя FictionBook Editor Next.
4. Откройте критическое событие и скопируйте подробности.

Особенно важны: имя сбойного приложения и модуля, код исключения, смещение,
версии приложения и модуля. Альтернатива: `Win + R` → `eventvwr.msc` →
«Журналы Windows → Приложение» → событие `Application Error` в момент сбоя.

## Расширенный дамп — только по запросу разработчика

Обычно встроенных `.dmp` достаточно. Если потребуется полный дамп, можно
использовать ProcDump:

```text
procdump.exe -accepteula -ma -e -x C:\FBE-Dumps "C:\Program Files\FictionBook Editor Next\FBE.exe"
```

Либо для уже запущенной программы:

```text
procdump.exe -accepteula -ma -e FBE.exe C:\FBE-Dumps
```

Полный дамп может содержать личные данные. Не публикуйте открыто книги с
ограничениями на распространение, персональные данные, пароли, токены и
закрытые ссылки. Если файл необходим для воспроизведения, но его нельзя
опубликовать, сообщите об этом и предложите сокращённый пример или непубличную
передачу.

## Рекомендуемая структура архива

```text
FBE-bug-report.zip
├─ README.txt
├─ book.fb2
├─ screenshot.png
├─ FBENext-crash-20260702-154233-000-pid1234.txt
├─ FBENext-crash-20260702-154233-000-pid1234.dmp
└─ FBE-Diagnostics.zip
```

В `README.txt` достаточно продублировать версию FBE Next, Windows, тип сборки,
шаги, фактический результат и повторяемость проблемы.
