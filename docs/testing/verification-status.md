# Статус верификации и пробелы покрытия

> Тип: Реестр статусов, не новый акт испытаний. Документационная база: FBE Next 3.0.9, `master` / `1ad7c507d1ed`; сверка 19 октября 2026 года.

## Граница этого документа

Реорганизация документации не является повторным runtime-прогоном FBE. Исторические проверки относятся к указанным в соответствующих отчётах ревизиям и не подменяют текущую приёмку.

## Общие непроведённые или требующие новой записи проверки

Реальная Windows 7 SP1, интерактивный UAC, физический переход между мониторами различного DPI, High Contrast и реальные книги сообщества проверяются в подходящей среде. До нового прогона не наследуйте PASS от source-contract или от другой ОС.

Открытые issues #43, #44, #45, #46, #49 и #59 проверялись при подготовке исходного аудита и остаются ссылками на живой трекер. Наличие реализованного этапа не означает закрытия всего issue. Текущую очередь смотрите в [TODO](../todo.md).

## Как обновлять

Добавляйте краткую запись: дата → commit/build SHA → область → набор проверок → PASS/FAIL/NOT RUN/BLOCKED → артефакт → ограничения. Длинные пошаговые журналы помещайте в `testing/reports` или архив, а сюда включайте их итог и границы.

Проверки документации перечислены в [правилах сопровождения](../maintenance/policy.md); они не подменяют строки таблицы тестов приложения.

## Предрелизная сверка после 3.0.9

Исходный ориентир — `c2abe00b81728290bc8be14931b41668dee2e278`. Его локальный FullValidation завершился с кодом 0 по прежнему составу тестов, однако CI остановился на FBD/File Close. Исторический PASS не подтверждает отсутствовавшие в локальном контуре File Close, New Document Safety и scripting API 1.4/1.5/OLE-сценарии.

В предрелизном контуре эти матрицы берутся из тех же шагов `.github/workflows/build.yml`, что выполняются в CI. Каталог FULL включает их; `SkipEarlyRuntimeSuites` в CI сохраняет выполнение каждого тяжёлого сценария один раз. Локальный FullValidation не выдаёт общий PASS без реального OLE: нужен GitHub-hosted прогон с отдельной учётной записью либо его проверяемое свидетельство для того же SHA из успешного Build. Локальное выполнение OLE при этом остаётся NOT RUN.

Отдельный FULL-контур материализованного portable-пакета выполняет `create-release.ps1 -FullValidation`: сохранение, перенос и восстановление настроек/UID/панелей проверяет `test-portable-gui-state.ps1`. Каталог отмечает этот обязательный producer как `package-stage`; он не выдаётся за прямой вызов локального core-verifier. Готовность требует успешных `validate`, `build` и `package` одного SHA. Один успешный core FullValidation не заменяет упаковочную приёмку.

На Windows 11 адресная матрица FB2/FBD, Portable/Installed, ZIP/RAR и оба New Document Safety-сценария прошли после усиления проверки владельцев DOM в `RuntimeTestFileClose.inl`. Проверялись метаданные второй книги, текущая сессия, все узлы дерева, SHA-256 исходных файлов/архивов и отмена/сохранение изменений. Итоговый полный gate и CI следует указывать отдельно по фактическому SHA, а не наследовать из этой адресной проверки.

Windows 10 22H2 — POST-RELEASE: пользователь проверит опубликованную версию. Реальная Windows 7 SP1, High Contrast, системная Dark и ручная DPI/locale-матрица #66 — NOT RUN/DEFERRED до доступной среды. Эти ручные проверки не являются обязательными условиями текущей предрелизной приёмки. Проверка PE-импортов Windows 7 остаётся обязательной и не заменяет runtime.

Известные предшествующие расхождения на базе 28b6c9c6: test-note-creation-evidence.py отвергает исторический SHA RuntimeTestPortableState.inl; полный audit-script-cards.py останавливается на историческом baseline. Эти отказы воспроизводились на исходном HEAD до очистки. Они не закрыты изменением документации и не являются новым runtime-прогоном.
