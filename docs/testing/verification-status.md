# Статус верификации и пробелы покрытия

> Тип: Реестр статусов, не новый акт испытаний. Документационная база: FBE Next 3.0.9, `master` / `1ad7c507d1ed`; сверка 19 октября 2026 года.

## Граница этого документа

Реорганизация документации не является повторным runtime-прогоном FBE. Исторический большой перечень проверок сохранён в [архиве структурной верификации](../archive/validation/verification-status-before-reorganization.md). Он относится к указанным в нём ревизиям и не подменяет текущую приёмку.

## Реестр областей

| Область | Имеющееся основание | Что не следует из него автоматически |
| --- | --- | --- |
| Сборка, layout и происхождение | Исполняемые build/staging/verify-сценарии | Что они успешно запускались после этой правки документации. |
| XML API и Undo | Адресные исторические COM/JScript/runtime-отчёты | Общая совместимость каждого старого скрипта. |
| HTML Paste | Исторические отчёты по internal-history/plain-middle | Полная ручная совместимость с любой внешней программой. |
| Карточки | Инвентаризация, proposals, кодовые baseline и адресные результаты | Содержательная проверка всех утверждений и аварийных ветвей. |
| Диагностика | Последовательные privacy/runtime/package-проверки | Ручная Windows 7/DPI-матрица, если она не записана отдельно. |
| UI и каретка | Рабочие отчёты issues #43/#49 | Закрытие непроведённой общей приёмки или невоспроизведённой причины мигания. |
| Производительность | Измерения Phase A/B и адресные тесты | Отсутствие любой задержки на любой большой книге. |
| Shell | Source, COM и отдельные Explorer-прогоны | Все комбинации Windows/разрядности/режимов установки. |

## Общие непроведённые или требующие новой записи проверки

Реальная Windows 7 SP1, интерактивный UAC, физический переход между мониторами различного DPI, High Contrast и реальные книги сообщества проверяются в подходящей среде. До нового прогона не наследуйте PASS от source-contract или от другой ОС.

Открытые issues #43, #44, #45, #46, #49 и #59 проверялись при подготовке исходного аудита и остаются ссылками на живой трекер. Наличие реализованного этапа не означает закрытия всего issue. Текущую очередь смотрите в [TODO](../todo.md).

## Как обновлять

Добавляйте краткую запись: дата → commit/build SHA → область → набор проверок → PASS/FAIL/NOT RUN/BLOCKED → артефакт → ограничения. Длинные пошаговые журналы помещайте в `testing/reports` или архив, а сюда включайте их итог и границы.

Отдельный [отчёт сборки документации](../maintenance/validation.md) формируется офлайн-сборщиком. Он содержит фактические результаты локальной сборки архива и не подменяет строки таблицы тестов приложения.
