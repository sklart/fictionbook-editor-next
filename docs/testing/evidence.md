# Доказательства и контрольные входы тестов

> Тип: Действующая инструкция. База документации: FBE Next 3.0.9, `1ad7c507d1ed`, 19 октября 2026 года.

## Что считать доказательством

Результат испытания относится к указанным исходникам, SHA бинарника, ОС, режиму запуска и сценарию. Статическая проверка наличия файла или обработчика не доказывает прохождение GUI-сценария. Сохранённый JSON старого прогона не становится новым runtime PASS при повторном чтении.

В отчёте различайте PASS, FAIL, NOT RUN и ограничение проверяемой области. После изменения исполняемого скрипта прежние хеши подтверждают лишь историческую редакцию; новый успешный прогон не приписывается всем родственным сценариям автоматически.

## Файлы с особым режимом сохранения

Полный список и SHA-256 находятся в [реестре неизменённых файлов](../maintenance/protected-evidence.md). Сохранены исходные пути JSON baseline, reviewed proposals, классификации Undo, доказательств примечаний и скрипта 64. Также сохранён Markdown `script-card-undo-defects.md`: его хеш входит в машинную классификацию.

Переносить эти файлы можно только отдельной согласованной правкой потребляющих тестов. Не пересчитывайте хеши лишь ради того, чтобы скрыть несоответствие исходной и проверенной редакции.

## Производные отчёты

Большие `script-card-content-audit.json`, `.html` и `.md` являются результатами генерации, а не контрольными входами. Генератор направляет новые результаты в `out/reports/script-cards` и запрещает их запись внутрь `docs`. Исторические проверенные proposals остаются под контролем версий.

Если генератор отказал из-за несовпадения текущего кода с историческим baseline, сначала разберите причину; не отключайте проверку. Реорганизация документации не изменяет поведение комплектных скриптов, их исходные комментарии, BOM, кодировки или окончания строк.
