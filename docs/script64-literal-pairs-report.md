# Исправление скрипта 64: буквальные пары

Исходная редакция: 595e4c82988f3b9782ffa5e46081be308c6d4e7b.
Исправления текста и первая версия усиленного стенда выделены в 3b094cd3.

Список буфера больше не превращается в код: eval/Function не используются.
CRLF/LF/CR нормализуются; обычные пробелы удаляются, пустые строки пропускаются.
Все непустые строки проверяются целиком до BeginUndoUnit, длина — ровно две
кодовые единицы UTF-16. Прочитанные символы хранятся в массиве пар, замена
в каждом текстовом узле выполняется split(from).join(to). Кавычки, косая черта,
обратная косая черта, знаки регулярных выражений и доллар трактуются буквально.

В настоящем JScript старый объект перечислил собственные цифровые ключи сначала
по возрастанию, остальные — в порядке первого добавления. Дубли меняли значение
без переноса ключа. Это сохранено: последнее значение в первой позиции;
правила 21,1X превращают 2 в 1, а aA,bB,aC превращают ab в CB.
Каскад ab,bc превращает ab в cc. Унаследованные свойства прототипа не становятся
правилами замены: обрабатываются только явно прочитанные пары.

Основной обход текстовых узлов сохранён; оформление EM/STRONG проверяется вместе
с текстом. Обход останавливается сразу после конечного маркера. Ссылки на свои
маркеры сохраняются сразу после вставки, чтобы finally мог убрать их при сбое.
Точечное продолжение от d71995e1247fd2336c7fca2ea174ca2a832768a1 устраняет
конфликт ID и усиливает независимую очистку (см. результаты ниже).
В TEXTAREA заменяется только выделенный TextRange, с сохранением текста до/после.
Группа, открытая этим Run, закрывается в finally; API window.external не менялся.
Авторство и исходные сообщения сохранены. Однострочные INPUT не обрабатываются.

## Поведение до и после

| Контур | До | После |
|---|---|---|
| Обычные пары и метасимволы слева, кавычка, обратная косая черта | PASS | PASS |
| a$, b\, c" вместе справа, выделение abc | Ошибка строковой константы | PASS: доллар, обратная косая черта, кавычка |
| Смешанные спецсимволы слева/справа | Не подтверждено | PASS |
| Каскад и повторные ключи | PASS | PASS, семантика сохранена |
| Цифровые ключи | Порядок подтверждён перечислением объекта | PASS: совместимый порядок |
| CRLF/LF/CR, пробелы и пустые строки | Полный контур не подтверждён | PASS |
| Кириллица | Не запускалась в прежнем стенде | PASS |
| Нет выделения, пустой/неверный список, нет текста | Отказы проверялись частично | PASS: сообщение, прежний HTML, нет маркеров и новой/open группы Undo |
| Неверная строка после допустимой; 3 единицы UTF-16 | Не проверялось | PASS: отказ до изменений |
| Выделение через EM/STRONG и несколько текстовых узлов | Не проверялось | PASS, структура оформления сохранена |
| Часть TEXTAREA, сохранение префикса/суффикса | Не проверялось | PASS: xaby → xABy |
| Одна операция Ctrl+Z, затем Ctrl+Y | PASS в усиленном стенде | PASS: точные снимки всего HTML тела |
| Искусственная ошибка после изменения первого текстового узла | Не проверялось | Частичный результат остаётся; маркеры удалены, группа закрыта |

Штатный Run вызывается через Doc::RunScript и затем из сохранённого замыкания
стенда в настоящих FBE Win32 / MSHTML / JScript. Алгоритм не заменяется моделью.
Перехвачены только MsgBox/alert для проверки отказов. Для проверки ошибки
временно подменяется String.prototype.split: исключение на втором текстовом узле
после изменения первого; метод восстанавливается в finally стенда.

Результаты разбираются как полные строки имя=значение; обязательные ключи должны
встречаться ровно один раз со значением 1. Отрицательные тесты коллизии
special/replacement-special, пропуска, дубля и значения 10 проходят и в C++, и в PS.
Перед Undo/Redo очищается история после подготовки последнего примера; проверяется
одна операция с точным названием, отсутствие предыдущей после Undo и полное
совпадение исходного/изменённого innerHTML fbw_body. Отказы проверяются отдельно
на очищенной истории с сопоставлением состояния открытой родительской группы.

Результаты с хешами: [текущий прогон](script64-runtime-results.json),
[прогон до исправления](script64-before-safe-pairs.json).

## Оставшиеся ограничения

- Правило содержит две единицы UTF-16; замена Unicode-кодовых точек и строки
  произвольной длины не добавлялась. Обычные пробелы не могут быть символами пары.
- Правила каскадные; цифровые ключи идут первыми, дубли сохраняют первую позицию.
- При исключении закрытие группы и очистка маркеров не означают автоматического
  отката. Частичный результат воспроизведён и явно допускается предупреждением.
- История TEXTAREA проверяется отдельно от истории книги; конкретный результат
  текущего прогона приведён ниже и в JSON, без вывода о полном аварийном откате.
- Не проверялись все возможные повреждения DOM, нехватка памяти или все ветви
  внешнего COM. Статус полного аварийного отката не присваивался.

## Безопасность маркеров и история TEXTAREA, 15 октября 2026

Вместо фиксированных BlockStart/BlockEnd/CursorPosition используется свободный
ID fbe-script64-N с проверкой document.getElementById перед вставкой. Занятые
суффиксы пропускаются. После pasteHTML сохраняется ссылка на элемент, проверяются
точные ID, тег и служебный атрибут; ссылка помечается объектом текущего запуска.
Обход сравнивает ссылки, очистка проверяет запись и объект владельца. Существующие
ID не снимаются и чужие элементы не становятся маркерами.

Проверены отдельно три старых ID, все три одновременно и наличие
fbe-script64-1/fbe-script64-2. После замены сравниваются те же объекты и их outerHTML
(включая атрибуты и потомков); после Undo и Redo — полный innerHTML fbw_body.
Изменения в нескольких узлах EM/STRONG также сохранены.

Очистка пробует каждый маркер независимо. При отказе removeChild применяется
removeNode(false), сохраняющий возможных потомков. Флаг открытой собственной
группы сбрасывается перед единственным EndUndoUnit. Исходная ошибка обработки
имеет приоритет над последующими ошибками очистки, Ctrl+Z автоматически не вызывается.
Проверены ошибка на втором текстовом узле после изменения первого, отказ первого
removeChild и одновременный отказ removeChild/removeNode для первого маркера.
В последнем искусственном случае второй маркер всё равно удалён, группа закрыта,
исходная ошибка сохранена; первый удалить невозможно до снятия инъекции стендом.
Это предел максимально безопасной очистки, а не обещание удаления при отказе DOM.
Карточка прямо отражает возможность частичных изменений и такой оставшейся разметки.

TEXTAREA: перед Run создано xaby, выделены только ab, история подготовки удалена.
Проверяется фактическое value поля и сохранность остальных элементов после штатных
команд редактора Undo/Redo. Перед командами стенд явно восстанавливает фокус FBE
и самого поля, чтобы проверить маршрут Ctrl+Z/Ctrl+Y. Искусственная история поля
не добавлялась. Итог: **PASS**, xaby → xABy → xaby → xABy; textarea-undo=1, textarea-redo=1.
Наблюдения и хеши записаны в script64-runtime-results.json.

Собран только FBE Release Win32 v143 / VC Tools 14.44.35207, FbeStrictWarnings=true
(/W4 /WX), из отдельного checkout. Подготовленные библиотеки зависимостей и заголовки
Hunspell/Lexilla переиспользованы из основного checkout; vendor-код не изменялся.
Первой сборке не хватало заголовков Lexilla в новом checkout; после подключения
существующих заголовков сборка завершена. Исходники посторонних изменений не включались.
Полная сборка solution, verify-release и длительные E2E не запускались.

Начальные прогоны выявили разовый OpenClipboard в прежнем тесте дубликатов и потерю
фокуса перед Undo в новом стенде. Восстановление фокуса сделано явно. Строка 378 временного скрипта соответствовала
setData буфера, получившему OpenClipboard. В стенде добавлен ограниченный повтор
только этой ошибки (до 1 секунды); повтор Run разрешён только при прежних DOM/value,
никакие частичные изменения не переигрываются. Это реальный clipboardData, данные
не подменяются. Результаты неуспешных прогонов не трактовались как PASS. Сохранён итог последнего прогона.

Снимок, индекс, актуальная запись отчёта и предложения обновлены только для скрипта 64.
Остальные 578 исполняемых файлов и записи остальных 91 замечания Undo не менялись.
Повторный аудит всего комплекта не выполнялся; проверка SHA/схемы каталога — отдельный
короткий контракт согласованности метаданных.

После полного PASS дополнительная попытка повтора была остановлена до запуска FBE:
буфер AnyDesk объявил AnyDesk_DataObject, но не выдал данные для сохранения.
Буфер не изменялся. Косметическая правка отступов C++-стенда, ради которой выполнялся
этот повтор, отменена. Возвращены точные исходники и EXE успешного полного прогона,
совпадение всех SHA стенда и EXE проверено. Дополнительная успешная сборка отражена
отдельно в additionalBuild JSON; её бинарнику отдельный runtime-PASS не присваивается.

После восстановления доступного буфера дополнительный запуск с лимитом 30 секунд
остановился без отчёта. Следующий запуск с TimeoutSeconds=60 завершился полным
**PASS** на точных итоговых исходниках и EXE: все пять конфликтов ID, три режима
очистки, Undo/Redo книги и TEXTAREA подтвердились повторно. Все исходные форматы
буфера восстановлены; clipboard-restored=1. Незавершённых runtime-проверок нет.
