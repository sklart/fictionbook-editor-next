# Остаточные замечания HTML Paste

База: `670542bc964a872bb1cece5b3bd72c20138e30ab`.
Работа изолирована в ветке `codex/html-paste-followup`; изменения основного
checkout не переносились в проверочную сборку.

## Причины и исправления

- Статический тест требовал старые вызовы с `scopeNode`. Текущий код проверяет
  преобразование на отсоединённой копии `copyScope`, затем записывает изменения
  живого `transform` нативно. Тест теперь проверяет оба прохода, их порядок,
  закрытие/откат транзакции, передачу HRESULT, границы ClipboardPastePreparer,
  определение области по обоим концам выделения и владение ресурсами.
  Он включён рядом с проверками VisualDomNormalizer в `verify-release.ps1`,
  который уже вызывается CI; отдельный дублирующий запуск не добавлен.
- OnRealPaste не проверял PostMessage. Теперь отказ исключает запрос из очереди,
  отменяет вставку и оставляет только восстановление отменённого события MSHTML.
  Зарегистрированный при создании Body обработчик простоя выполняет его после
  возврата из события, без второго PostMessage. Проверяются неизменность полного
  документа и состав истории; удаляются только доказанные пустые события и их
  обратные записи, затем возвращаются прежние Undo/Redo, выделение и savepoints.
- Несколько событий использовали общий снимок, но каждое ставило независимую
  команду, которая позже читала текущий буфер. Теперь одна отложенная команда
  обрабатывает FIFO отдельных снимков HTML, текста, признака внутреннего
  копирования и выделения. Поколение очереди отбрасывает устаревшие сообщения.
  При повторе в той же точке следующая вставка продолжает от новой каретки.
  Каждая вставка использует существующую нативную группу Undo. Навигация сбрасывает
  отложенное состояние, обработчик простоя снимается при уничтожении view.
- Обычный текст из снимка записывается через нативный TextRange: это сохраняет
  соединение первой/последней строк с исходным абзацем, как у прежнего Ctrl+V.
  PlainTextToHtml и команда Paste Text не изменены. Прочие форматы сохраняют
  прежний путь ClipboardPastePreparer/native paste, с отказом при смене буфера
  до обработки запроса вместо вставки чужого содержимого.

Очередь проверяется настоящими событиями MSHTML: два/три события вызываются
до обработки первого отложенного сообщения. Между ними меняется буфер, затем
он меняется ещё раз перед обработкой. Эталон — последовательные вставки прежним
прямым путём; сравниваются полный DOM и координаты выделения после каждого
Undo/Redo. Проверяется количество шагов и отдельная отмена предыдущей нативной
правки до чистого документа. Отказ PostMessage вводится только в test-mode;
восстановление выполняется через настоящий WTL OnIdle.

## Артефакты и ограничения

Host: Windows NT 10.0.26300.0. Запуск на Windows 7 не выполнялся;
совместимость с ней и реальными книгами FBE 2.8.5 не объявляется подтверждённой.
Публичные COM/JavaScript API, пользовательские скрипты, vendor-код и dependency
DLL не менялись. Архитектура Undo повторно не перерабатывалась.

Выполнена итоговая сборка затронутого FBE Release Win32 с готовыми pinned
vendor-библиотеками и отдельными obj/generated/output. До неё были диагностические
инкрементальные сборки: исправлены const-аргумент ReportError, предупреждение
о затенении локального имени и снятие idle handler после удаления регистрации
цикла из модуля. Последний дефект давал аварийное завершение уже после PASS
проверок отказа; окончательные процессы завершаются штатно. Дополнительная
проверка обычного текста выявила отличие HTML-конвертации от нативной вставки;
исправление TextRange проверено тем же эталоном без ослабления условий.

Артефакты: `out/tests/html-paste-followup/` внутри проверочного worktree.
Итоговая сборка: `release-win32-text.log`; runtime: `queue-final.log`,
`required-real.log`, `regression-real.log`; TSV и сохранённые FB2 скопированы
в `evidence/`, поэтому результат не зависит от сохранности Temp.

SHA256 итогового FBE.exe:
`3BC56307C188C1293ED2E93307543A6E9AD895E07121D1B68635B3C8614AAD98`.
SHA коммита исправления приводится в итоговом сообщении и manifest.json
