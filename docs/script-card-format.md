# Карточки скриптов FBE Next, схема 1

Карточка — JSON в UTF-8 с прежними полями схемы 1. Для штатного скрипта `Scripts\категория\имя.js` используемая редактором карточка находится в `Settings\ScriptCards\категория\имя.json`; в Portable каталог Settings находится в фактическом DataPath, установленная версия использует пользовательский каталог настроек. Для скрипта вне штатного каталога используется файл JSON `ScriptCards\_external\<sha256>.json.fbe-external`: хеш вычисляется от абсолютного пути Windows после приведения к нижнему регистру, в UTF-16LE без BOM. Суффикс не совпадает с именами штатных карточек и исключает конфликт с ними. Индекс `Scripts\script-cards.index.json` является производным и не требуется для открытия карточки.

Сохраняются обязательные поля `schema`, `title`, `version`, `authors`, `summary`, `description`, `scope`, `modifiesDocument`, `requiresSelection`, `usage`, `warnings`, `dependencies` и `sourceRevision`, а также прежние дополнительные поля настроек, Undo, примеров, истории, ссылок и авторства. Перенос меняет только алгоритм `sourceRevision.algorithm`; содержание описаний и ранее сохранённый хеш кода остаются прежними.

Исходные штатные карточки для поставки находятся в `runtime\ScriptCards`. При инициализации каталога скриптов отсутствующая карточка копируется в пользовательский каталог. Контрольные суммы поставленных копий хранятся в `.fbe-defaults.ini`. Существующая карточка не перезаписывается: если новая поставленная редакция отличается, она сохраняется рядом с именем `<имя>.json.fbe-new-<хеш>` для сравнения. Это консервативная политика и для неизменённой старой копии. Удаление скрипта не удаляет пользовательскую карточку. После редактирования файла обновляется предварительный просмотр; код скрипта для построения дерева не хешируется.

## Совместимость и контроль редакции

Внешняя карточка имеет приоритет над встроенной. Если внешний файл существует, но повреждён, отображается ошибка; автоматического перехода к встроенному описанию нет. При отсутствии внешнего файла поддерживаются оба старых блока `FBE-SCRIPT-CARD` и `FBE-NEXT-CARD` непосредственно после BOM; без карточки сохраняется прежнее поведение.

`sourceRevision.algorithm` внешней карточки — `sha256-raw-js-v1`: SHA-256 всех фактических байтов JS, включая BOM, комментарии и окончания строк. Для встроенных карточек остаётся `sha256-exclude-fbe-card-v1`: из исходного потока исключается точный диапазон встроенного блока с одним следующим переводом строки. Совпадение хеша подтверждает только редакцию кода, а не корректность описания или безопасность. Статусы — Missing, Invalid, Unchecked, Current и Changed. Зависимости проверяются отдельно; связанные JS по-прежнему хешируются без встроенной карточки.

## Утилиты

```powershell
py -3 tools/script-card-tool.py inspect runtime/Scripts/example.js
py -3 tools/script-card-tool.py validate runtime/Scripts/example.js
py -3 tools/script-card-tool.py stamp runtime/Scripts/example.js --accept-revision
py -3 tools/script-card-tool.py inspect C:/portable/Scripts/example.js --scripts-root C:/portable/Scripts --cards-root C:/portable/Data/Settings/ScriptCards
py -3 tools/generate-script-card-index.py --check
```

`--card` задаёт отдельный внешний JSON, в том числе для скрипта вне стандартного дерева. `stamp` требует явного `--accept-revision`, меняет только карточку и не подтверждает содержательную проверку. `--resource-root` задаёт корень для проверки зависимостей. Повреждённый внешний JSON не заменяется встроенным.

Для отдельной миграции используйте `tools/externalize-script-cards.py --scripts <копия-Scripts> --cards <отдельный-каталог> --report <отчёт.json>`; без `--apply` выполняется только проверка. С `--apply` удаляется только точный встроенный диапазон, а остальные байты и хеш проверяются. Существующая отличающаяся карточка считается конфликтом и не перезаписывается. Утилита поддерживает повторный запуск и не предназначена для молчаливого изменения пользовательских скриптов при запуске редактора.
