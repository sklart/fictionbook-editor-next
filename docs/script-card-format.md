# Встроенная карточка скрипта FBE Next, схема 1

Источник сведений — сам `.js`. Поисковые индексы и миграционные каталоги являются производными файлами. Пример структуры и обязательных полей приведён в ТЗ; служебная реализация находится в `tools/script-card-tool.py`.

## Положение и кодировка

- Блок начинается непосредственно после BOM, если он есть, без пробелов или других строк перед ним. Допускается ровно один основной блок.
- Маркеры: `/*<FBE-NEXT-CARD version="1">` и `</FBE-NEXT-CARD>*/`. После закрывающего маркера обязателен один добавленный перевод строки (`CRLF`, `LF` или `CR`). Этот перевод строки входит в блок.
- Маркеры и JSON сериализуются в кодировке исходного файла. При BOM используются UTF-8, UTF-16LE или UTF-16BE. Для файла без BOM утилита принимает UTF-8 при строгом декодировании, иначе Windows-1251; при неоднозначности кодировка задаётся явно `--encoding`.
- В JSON не допускаются повторяющиеся ключи, сырое `*/` в теле комментария и блок длиннее 65536 байт в кодировке файла. Не представимые в старой кодовой странице символы записываются JSON-экранированием `\uXXXX`.
- Существующий код, BOM, пробелы, авторские комментарии и окончания строк не изменяются. Для проверки миграции удаление точного диапазона блока должно побайтно восстановить исходный файл.

## `sha256-exclude-fbe-card-v1`

1. Прочитать все байты файла без перекодирования.
2. Если после BOM расположен корректный блок, удалить диапазон от первого байта открывающего маркера до конца **одного** перевода строки непосредственно после закрывающего маркера. BOM не удалять.
3. Если блока нет, использовать все байты файла.
4. Вычислить SHA-256 оставшихся байтов и записать 64 строчные шестнадцатеричные цифры в `sourceRevision.sha256`.

Смена только JSON в пределах блока не меняет хеш. Любой байт вне блока, включая окончания строк и BOM, меняет хеш. Совпадение хеша означает только идентичность редакции кода и не подтверждает правильность описания или безопасность. `sourceRevision.reviewStatus` (`generated`, `reviewed`, `unknown`) является отдельной декларацией; команда `stamp` **не** меняет его автоматически.

Результат `inspect`: `missing`, `invalid`, `unchecked`, `current` или `changed`. Проверка связанных файлов возвращает отдельный статус. Если `dependenciesComplete` не заявлен явно, даже пустой список зависимостей имеет статус `unverified`. `validate` возвращает ошибку при изменённой или недопустимой зависимости, даже когда сам JS соответствует карточке. Нативная проверка открывает фактический файл и сверяет его конечный путь с разрешённым корнем перед хешированием; вызывать её следует при просмотре карточки, не из отрисовки дерева.

Для связанного файла `.js` поле `dependencies[].sha256` использует тот же алгоритм исключения встроенной карточки. Для остальных файлов это SHA-256 всех байтов. Таким образом, правка документации связанного скрипта не меняет статус его исполняемой редакции.

## Служебные команды

```powershell
py -3 tools/script-card-tool.py inspect runtime/Scripts/example.js
py -3 tools/script-card-tool.py validate runtime/Scripts/example.js
py -3 tools/script-card-tool.py stamp runtime/Scripts/example.js --accept-revision
```

`stamp` требует явного `--accept-revision`; перед ним нужно проверить изменение кода и описание. Запись атомарна и меняет только блок карточки. `--resource-root` задаёт корень для проверки буквальных относительных путей зависимостей. Выход за этот корень, абсолютные пути и переходы `..` отклоняются. Неизвестные и динамические зависимости остаются непроверенными.

`tools/generate-script-card-index.py --generate` строит `runtime/Scripts/script-cards.index.json` только из встроенных карточек. `--check` проверяет его актуальность; этот режим входит в CI. Индекс можно удалить и восстановить, просмотр карточки от него не зависит.

Каталог `FBE-Next-Script-Cards-b8312c48` относится к Git tree `64c413305ea8f953981f3aa1a2c79a1baff4086f`. Его `source.sha256` вычислен для канонических Git-байтов. При развёртывании с CRLF локальный SHA может отличаться: мигратор сначала сопоставляет Git blob, а затем вычисляет новый отпечаток именно установленных байтов без блока. Нельзя автоматически приравнивать несовпадение локального SHA каталога к изменению алгоритма скрипта.
