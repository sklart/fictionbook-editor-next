# Справка по регулярным выражениям — Дизайн

## Движок

Поиск в Дизайне использует **PCRE2-16**; режим UTF включён всегда. Это не движок Source/Scintilla.

## Unicode и UCP

UTF сохраняет Unicode-текст. Включите **Unicode (UCP)**, когда `\w`, `\b` и свойства символов должны учитывать буквы всех алфавитов. Используйте `\p{L}`, `\p{N}` и `\P{...}`.

Без UCP `\b` и `\w` работают по базовым правилам движка. С UCP `\b(\p{L}+)\b` распознаёт кириллицу и другие Unicode-слова.

## Символы и экранирование

Обычные символы совпадают сами с собой. Экранируйте метасимволы через `\`: `\\`, `\t`, `\r`, `\n`, `\R`, `\xNN`, `\x{...}`. Точка `.` означает один символ.

## Классы символов

Доступны `[abc]`, `[^abc]`, диапазоны `[a-z]`, а также `\d`, `\s`, `\w` и их отрицания. Для многоязычных книг предпочтительнее явно указывать Unicode-свойства.

## Якоря и границы

`^` и `$` — якоря строк; `\A` и `\z` — якоря всего текста. `\b` и `\B` — границы слова, `\G` продолжает от предыдущего совпадения.

## Квантификаторы

| Синтаксис | Значение |
| --- | --- |
| `.*` | жадный: забирает максимум |
| `.*?` | ленивый: забирает минимум |
| `.*+` | possessive: не делает откат |
| `{n,m}` | от n до m повторов |

Ленивый квантификатор берите для ближайшего закрывающего разделителя; possessive — только когда откат не нужен.

## Группы и обратные ссылки

Группы: захватывающая `(…)`, незахватывающая `(?:…)`, именованная `(?<name>…)`, атомарная `(?>…)`. Обратные ссылки: `\1`, `\k<name>`.

```regex
(?<word>\p{L}+)\s+\k<word>
```

Это возможный повтор слова при включённом UCP.

## Альтернатива и lookaround

`a|b` задаёт альтернативу. Lookahead: `(?=…)`, `(?!…)`; lookbehind: `(?<=…)`, `(?<!…)`.

```regex
(?<=№)\s+(?=\d)
```

## Inline options

`(?i)`, `(?m)`, `(?s)`, `(?x)` включают игнорирование регистра, multiline, dotall и расширенный режим. Локальная форма: `(?i:слово)`.

## Advanced PCRE2

Поддерживаются conditionals, branch reset `(?|…)`, подпрограммы `(?1)` / `(?&name)`, `\K` и `(*SKIP)(*FAIL)`.

```regex
"[^"]*"(*SKIP)(*FAIL)|\bслово\b
```

Первая альтернатива пропускает цитаты перед поиском слова.

## Замена в FBE

Это **грамматика замены FBE**, а не `pcre2_substitute`: `$0`/`\0` — всё совпадение, `$1`…`$9`/`\1`…`\9` — группы, `$+`/`\+` — последняя группа. `\U`, `\L`, `\T`, `\Q`, `\S`, `\E` меняют регистр или форматирование FBE.

До → шаблон/замена → после:

```regex
Найти:   (\d+)\s*[-–—]\s*(\d+)
Заменить: $1–$2
```

`12 - 15` станет `12–15`.

## Практические книжные примеры

- Несколько пробелов: `[ \t]{2,}` → один пробел.
- Пробел перед пунктуацией: `[ \t]+([,;:!?])` → `$1`.
- Возможный повтор слова: `\b(\p{L}+)\s+\1\b` с UCP — требует проверки.
- Смешение кириллицы и латиницы: `(?=[^\r\n]*[А-Яа-яЁё])(?=[^\r\n]*[A-Za-z])[^\r\n]+` — подозрительно.
- Пунктуация внутри слова: `\p{L}[,;:]\p{L}` — возможная ошибка OCR.
- Строчная→заглавная OCR: `\p{Ll}\p{Lu}` — требует проверки.
- Числовой диапазон: `(\d+)\s*[-–—]\s*(\d+)` → `$1–$2`.
- Инициалы: `\b([A-ZА-ЯЁ])\.\s*([A-ZА-ЯЁ])\.` → `$1. $2.`.
- Прямые кавычки: `"([^"]+)"` — заменяйте по редакционной политике.
- Три точки: `\.\.\.` → `…` при допустимости замены.
- Скрытый Unicode: `[\x{00AD}\x{200B}-\x{200D}]` — подозрительные невидимые символы.
- Возможная пропущенная точка: `\p{Ll}\s*\n\s*\p{Lu}` — только проверка.
- Неразрывный пробел после №: `№\s+(?=\d)` → `№ `.
- Неразрывный пробел после §: `§\s+(?=\d)` → `§ `.
- Подозрительные Unicode-пробелы: `[\x{2000}-\x{200A}\x{202F}\x{205F}\x{3000}]` — требует проверки.

## Частые ошибки и ограничения

Экранируйте буквальные знаки regex. ReviewOnly-шаблоны не заменяйте массово без просмотра. В Дизайне доступны PCRE2-16, UTF/UCP и расширенные конструкции; Source использует построчный Scintilla C++11. FBE заменяет только группы 1…9 и не заменяет через абзацы.
