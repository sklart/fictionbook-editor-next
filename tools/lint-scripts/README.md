# Проверка встроенных JavaScript-скриптов

Встроенные скрипты FictionBook Editor запускаются старым Microsoft JScript.
Поэтому ESLint проверяет все поддерживаемые файлы в `runtime/` как обычные
скрипты ECMAScript 3, а не как современные Node.js-модули.

## Запуск

```text
npm ci
npm run lint:scripts
```

Проверяются JavaScript-файлы и inline-блоки `<script>` HTML, поставляемые с редактором: пользовательские
скрипты (`runtime/Scripts/`), файлы HTML-диалогов, общие скрипты,
`runtime/main.js`, `runtime/TreeCmd/` и утилита перекодирования. Каталоги
результатов сборки и временных файлов не попадают в проверку. Внешние
`<script src="...">` не извлекаются: соответствующие `.js` проверяются отдельно.
Адресно исключены сторонние `jquery*`, `jszip*`, `vendor/` и `generated/`,
поскольку этот код не сопровождается проектом.

## Глобальные объекты среды

Разрешённые глобалы перечислены в `eslint.config.js`: DOM/MSHTML (`window`,
`document`, `event`, `navigator`, `location`), интерфейс FBE (`external`),
диалоговые функции браузера и объекты Active Scripting (`ActiveXObject`,
`Enumerator`, `VBArray`, `GetObject`, `CollectGarbage`). Добавляйте новый
глобал только после подтверждения, что его предоставляет FBE, MSHTML или
JScript; укажите его в конфигурации, а не отключайте правило для всего файла.

## Правила и JScript

Проверка блокирует синтаксис, несовместимый с ES3, и безопасные ошибки:
дублирующиеся аргументы/ключи, недостижимый код, самоприсваивание, сомнительные
переносы строк, неверный `typeof`, сравнение с `NaN`, несуществующие имена и
повторные объявления. Глобалы FBE/MSHTML/JScript инвентаризированы в
`eslint.config.js`; новый глобал добавляйте только с подтверждением, что его
предоставляет соответствующий хост.

Исторические нарушения хранятся в `baseline.json`, поэтому CI запрещает новые,
изменённые и устаревшие диагностические сообщения. Исправление старой проблемы
обязательно сопровождается удалением её записи из baseline. Обновлять baseline
можно только сознательно после проверки изменений командой
`npm run lint:scripts:baseline`.

ESLint не запускает Microsoft JScript и не заменяет проверку в реальном FBE:
между ES3 и JScript возможны отличия. В CI Windows выполняется
`npm run test:lint-scripts:jscript`: он компилирует штатные `.js` и inline-блоки
HTML реальным `cscript.exe`, не исполняя код. Исторические несовместимости
зафиксированы адресно в `jscript-baseline.json`; новые и устаревшие записи
блокируют CI. Исключения для внешних библиотек, `vendor/` и `generated/`
совпадают с ESLint и остаются адресными.
