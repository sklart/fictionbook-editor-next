# Проверки документации

Python 3.10+, только стандартная библиотека. Из корня репозитория:

```text
python tools/tests/test-docs-tools.py
python tools/docs/doc_links.py --root .
python tools/docs/check_scripting_api.py --root .
```

Проверка ссылок охватывает docs, корневые Markdown и документацию tools, src, localization, packaging, runtime, .github; build/out и third_party исключены. Она проверяет относительные пути, Markdown/HTML-якоря, повторные заголовки, ссылки и изображения, не обращаясь к внешним сайтам. `--folder docs` ограничивает область. Это небольшой парсер, а не полная реализация CommonMark.

API-проверка извлекает публичные имена из IExternalHelper и ScriptingMethods, исключает внутренние context-методы, сверяет оглавление и уникальные api-якоря, число методов, версию и capabilities с ScriptingApi.inl. Устаревший снимок на 82 метода должен завершаться FAIL; число не закреплено в проверке и следует исходникам.

Адресные тесты проверяют отсутствие файлов-переадресаторов во всех Markdown/TXT каталога docs (цитаты и кодовые примеры допустимы), отрицательные случаи и изолированный вывод генератора аудита: Git из PATH, запрет записи в docs, ссылки HTML относительно заданного каталога. Исполняемые скрипты не изменяются.

Workflow `.github/workflows/docs.yml` выполняет эти три команды на Ubuntu. Локальная проверка YAML и выполнение команд не означают успешный запуск удалённого CI. Эти проверки не исполняют примеры JScript, не подтверждают ABI и не заменяют Windows/GUI/runtime или release gate.
