# Changelog

## [Unreleased]

- В режиме «Код» невидимые символы можно показывать компактными знаками, похожими на Microsoft Word, либо прежними текстовыми метками. Это влияет только на отображение и не меняет FB2.

- XML-подсказки режима «Код» теперь используют встроенную схему FB2: редактор предлагает допустимые элементы и атрибуты, закрывающие теги и ссылки на существующие идентификаторы документа.

- Улучшена работа режима «Код» с большими документами: сокращены лишние обновления редактора, а Undo/Redo лучше восстанавливает место редактирования. Ошибки XML отображаются возле проблемной строки. В «Настройках FBE Next» добавлена опция показа неразрывных, мягких и других невидимых специальных символов.

- Обновлены редакторные зависимости: Scintilla до 5.6.5 и Lexilla до 5.5.2. В режиме «Код» ширина поля номеров строк теперь проверяется только при изменении количества строк, а подсветка парных XML-тегов не пересчитывается при простой прокрутке.

- Основной Win32-исполняемый файл FBE теперь собирается с поддержкой Large Address Aware в конфигурациях Release и Debug, что позволяет использовать расширенное адресное пространство на 64-разрядных Windows без отказа от Windows 7 x86.

- Исправлена обработка слов с несколькими дефисами в окне «Слова»: Хо-ро-шо и более длинные цепочки больше не обрываются после первого дефиса; такие слова можно добавлять в список исключений вручную.

- В поставку добавлен каталог `Themes` с 21 внешней JSON-палитрой XML-подсветки: Code OSS, Solarized, Gruvbox, Everforest, Flexoki, Dracula, Nord, Catppuccin, Tokyo Night, Ayu, Rosé Pine, Night Owl и GitHub. Вместе с «Как в системе», FBE Light, FBE Dark и исторической FBE это даёт 25 вариантов выбора. Каждая тема содержит все 23 логические роли; загрузчик игнорирует неполные и некорректные файлы безопасно. Источники и лицензии собраны в едином `THIRD-PARTY-NOTICES.md` и `THIRD-PARTY-LICENSES`, а release-проверки контролируют состав каталога.

- Проверка орфографии больше не разрывает слова из-за мягкого переноса U+00AD. Мягкие переносы исключаются перед обращением к Hunspell и перед добавлением в пользовательский словарь или список игнорирования, но остаются в тексте FB2 без изменений.

- На вкладке «Настройки FBE Next» можно отдельно настроить фон редактора исходного кода. Рядом с выбором схемы и цветов добавлен живой XML-предпросмотр: он обновляется до сохранения настроек при смене схемы, фона, текста, тегов, атрибутов, строк и комментариев.
- Подсветка XML в режиме «Код» теперь применяет выбранную цветовую схему
  сразу после закрытия настроек: палитра включена в снимок конфигурации
  редактора. Таблица стилей расширена на XML-декларации, CDATA, комментарии
  и SGML-конструкции Lexilla.
- Основа оформления редактора исходного кода переведена на стабильные
  логические роли XML и редактора (теги, разделители, атрибуты, значения,
  комментарии, CDATA, сущности, инструкции, DOCTYPE, ошибки и предупреждения).
  Номера стилей Lexilla изолированы в одном сопоставлении; историческая
  светлая схема сохранена, а пользователь может переопределить основные
  группы цветов поверх выбранной палитры.

- Исправлено отсутствие пункта «Диагностический журнал…» в меню «Сервис»
  при русском и украинском интерфейсе: сгенерированные MENU-ресурсы и их локальные
  заголовки синхронизированы с основной командой.

- Подготовлен предварительный выпуск 3.0.7: GitHub Actions распознаёт теги
  `vX.Y.Z-rc.N`, публикует их как предварительные выпуски и не меняет стабильный манифест
  автообновления. Проверка Modern/Win7 архивов теперь считает различие
  пересобираемых Batch-конвертеров ожидаемым и контролирует, что Win7-вариант
  действительно создан.
- Исправлено падение GitHub Actions на этапе создания артефактов: аудит
  кириллицы в C/C++ строковых литералах остаётся частью release-проверки и
  выводит сводку, но больше не блокирует выпуск из-за накопленного
  исторического набора строк. Строгий режим сохранён для изолированных
  regression-fixture и дальнейшей локализации новых участков.
- Portable-пакет для Windows 7 теперь повторно собирает все три пакетных
  конвертера (`ExportDOCXBatch.exe`, `ExportEPUBBatch.exe`,
  `ImportEPUBBatch.exe`) с API-уровнем Windows 7, поэтому экспорт EPUB больше
  не требует отсутствующую в этой системе функцию `CreateFile2`. При запуске
  любого Batch-конвертера двойным щелчком вместо мгновенно исчезающего окна
  выводится понятная подсказка о запуске из командной строки или PowerShell.
- Оптимизирован GitHub release-конвейер Modern/Win7: общие FBE, плагины,
  FBV, property handler, MUI и зависимости собираются один раз, а второй этап
  компилирует только отдельные `Scintilla.dll`/`Lexilla.dll` для Win7. Упаковка
  получает DLL явным путём; проверка архивов подтверждает идентичность общих
  бинарников и различие Win7-варианта Scintilla.
- Добавлен диагностический журнал, включаемый переменной окружения
  `FBE_NEXT_TRACE` или через «Сервис → Диагностический журнал…»:
  `%LOCALAPPDATA%\FBE Next\fbe-trace.log` содержит время, последовательность,
  длительность, PID/TID, категорию, уровень и код операции. Он фиксирует команды
  и горячие клавиши, переходы и выделение, операции документа, XML/XSLT,
  HTML-компонент, плагины, настройки, восстановление, скриптовые интерфейсы и
  HRESULT/COM-сбои. Текст книги, пути файлов, содержимое скриптов и base64 не
  записываются; размер текущего файла ограничен 4 МБ, а предыдущий запуск
  сохраняется как `fbe-trace.previous.log`. Пункт меню изменяет режим для
  следующего запуска и предупреждает о необходимости перезапуска;
  Выбор из меню сохраняется в настройках FBE, поэтому отключение не отменяется
  унаследованным значением переменной окружения. при работе с
  журналом в заголовке отображается «Диагностика», а на запуске предлагается
  отключить режим. Прежние отдельные переменные трассировки запуска и переноса
  выделения удалены.
- На вкладке «Настройки FBE Next» добавлены базовые цветовые схемы XML-подсветки:
  «Как в системе», FBE Light, FBE Dark и историческая FBE. Новые профили по
  умолчанию используют «Как в системе»: Windows 10/11 выбирает FBE Light или
  FBE Dark по системной теме, а Windows 7 и случаи ошибки определения безопасно
  используют FBE Light. Ранее сохранённые контрастная и тёмная схемы
  автоматически переводятся в FBE Light и FBE Dark; подписи доступны во всех
  12 runtime-локализациях и встроенных русской/украинской resource DLL.
- Исправлен переход из «Тела» в «Код»: вспомогательный JavaScript-вызов больше не передаётся через неверный вариант Active Scripting, а компактная сериализация `<binary>` не использует неподдерживаемый MSXML6 `put_text`, вызывавший COM-ошибку `0x80070057`.
- Исправлена настройка отображения неразрывного пробела: символы выбора больше не превращаются в вопросы, а смена обозначения применяется к уже открытому документу.
- Исправлена загрузка пользовательских скриптов portable-версии из путей с
  кириллицей: формирование пути больше не ограничено фиксированным буфером
  `MAX_PATH`, а настройка папки `Scripts` сохраняет исходный Unicode-регистр.
  Диагностический журнал дополнительно фиксирует каталог скриптов и их число.

- Диагностика ошибок пользовательских JavaScript-скриптов при загрузке теперь выводит тип и этап ошибки, имя и путь файла, координаты, фрагмент исходного кода с указателем, исходное сообщение JScript и HRESULT; сведения можно скопировать в буфер обмена.
- При сохранении FB2 base64-содержимое `binary` записывается компактно, без
  автоматически добавляемых MSXML переводов строк; допустимые тире в именах
  вновь добавляемых изображений сохраняются в `binary id`. Замена base64
  выполняется через текстовый DOM-узел, а не через `put_text` элемента;
  оптимизация запускается только при сохранении и не участвует в переходе
  редактора в режим «Код».
- Устранён источник подвисания проверки орфографии после локального изменения
  конца длинного раздела: видимая область больше не ищется обходом всех
  абзацев документа, а подчёркивания обновляются только для изменённого
  абзаца.

## [3.0.6] - 2026-07-15

- На странице компонентов установщика увеличено поле описания, а пояснения
  сокращены и выровнены для всех базовых локалей. Описание набора скриптов
  теперь корректно указывает на сообщество, без устаревшей ссылки на Jurgennt.

- Установщик теперь регистрирует экспортные плагины в пользовательском разделе
  реестра, поэтому ExportHTML, ExportDOCX и ExportEPUB не требуют прав
  администратора. Сборка setup требует Unicode-вариант NSIS: это исключает
  повреждение русских сообщений установщика при отсутствии плагина.

- При переключении между Body и Source сохраняется выделение в обоих
  направлениях; обратный переход теперь не восстанавливает устаревший диапазон
  Body, если выделение Source нельзя сопоставить с отображаемым текстом.

- Локализованные DLL FBE теперь формируются сразу в `Lang\ru-RU` и
  `Lang\uk-UA`; корневые дубли `res_rus.dll` и `res_ukr.dll` удалены из
  результата сборки и запрещены release-проверками.

- Все вкладки окна настроек используют единый шрифт `Tahoma 8`, выбранный по
  образцу страницы «Слова»; правило применяется также к русской и украинской
  resource DLL.
- Полностью документирован API `window.external` для пользовательских
  JavaScript-скриптов: 28 методов и свойство `inflateBlock` снабжены
  сигнатурами, ограничениями, примерами входных и выходных данных и
  оглавлением с быстрыми переходами.
- В настройки добавлена вкладка «FBE Next» с управляемым созданием резервной
  копии `.bak` при сохранении существующей книги. Настройка включена по
  умолчанию; отключение не меняет безопасную запись через временный файл.
- Исправлены повреждённые русские и украинские строки resource DLL: подсказки
  панели инструментов и имена команд в настройках больше не отображаются как
  последовательности вопросительных знаков.
- В ExportDOCX устранено предупреждение PVS-Studio о некорректном
  многосимвольном литерале для знака «№» при распознавании заголовков сносок.

## [3.0.5] - 2026-07-15

- Установщик получил стартовые переводы видимых компонентов и финальной страницы
  для девяти дополнительных европейских языков. Генерация больше не создаёт
  повторные строки NSIS, поэтому предупреждения сборки не маскируют реальные
  проблемы упаковки.
- Исправлено отображение финальной страницы установщика: текст и флажок запуска
  FBE Next больше не должны показывать mojibake или обрезаться.
- Выпускной сценарий теперь проверяет локализованные DLL внутри `Lang` в
  portable-архивах и всегда берёт текущую версию заметок из `src/version.h`.
- Локальная сборка PCRE2 выбирает CMake из фактически установленной Visual
  Studio и корректный генератор Visual Studio 2026; это устраняет зависимость
  от случайной CMake-копии из `PATH`.
- Обновлены Scintilla до 5.6.4 и Lexilla до 5.5.1 с накопленными upstream-
  исправлениями редакторного компонента и лексеров.
- Иконки FBE Next заменены на прозрачные варианты без белого фона. Профиль,
  история, словари и регистрации Next окончательно отделены от старого
  FictionBook Editor; после обновления пользовательские параметры нужно один
  раз проверить и при необходимости настроить заново.
- В режиме исходного XML восстановлено отображение XML-декларации, а «Сохранить
  как» добавляет новый файл в список последних документов.
- В списке языков FBE теперь показываются только фактически установленные
  пакеты `Lang/<locale>`; удалённый вручную пакет также исчезает из списка.
- Смена только языка больше не выполняет тяжёлую повторную настройку редактора,
  Scintilla и орфографии, поэтому интерфейс должен переключаться заметно быстрее.
- Resource DLL русского и украинского интерфейса больше не выгружаются во время
  live-переключения языка, что устраняет риск аварийного завершения и повреждения
  отображения уже созданных окон.
- Исправлено аварийное завершение после смены только языка: этот путь больше не
  пытается сериализовать не изменявшиеся группы горячих клавиш старым XML-кодом.
- Смена языка больше не создаёт заново плагины, скрипты, значки меню и кнопки
  панели инструментов: устранены нарастающее потребление памяти, задержки и
  визуальные артефакты интерфейса после нескольких переключений.
- Исправлено live-переключение языка главного окна: WTL CommandBar теперь
  обновляет подписи уже созданных верхних пунктов меню без повторного
  присоединения или разрушения `HMENU`. У служебных панелей ссылок и таблиц
  одновременно обновляются подписи и разметка, поэтому текст не должен
  накладываться после смены языка; прежние подписи горячих клавиш также не
  накапливаются при повторных переключениях.
- Release-gate теперь дополнительно проверяет, что в пользовательских
  C/C++-строках не появляется зашитая кириллица в обход JSON-локализации.
  Сам анализатор исправлен для корректной обработки экранированных обратных
  слешей и не принимает последующие комментарии за строковые литералы.
- Группа «Языки интерфейса» в установщике по умолчанию свёрнута.
- Добавлена инструкция по сбору сведений об ошибках и файлов crash dump.
- Сборка и release-gate теперь контролируют структуру runtime-локализации:
  языковые JSON-файлы и resource DLL размещаются только в `Lang\<locale>`,
  без пустых устаревших каталогов локалей в корне `out\Release`.
- Публикация GitHub-релиза теперь автоматически возвращает в `master` манифест
  автообновления с SHA-256 именно CI-собранного установщика.
- Release-gate больше не сравнивает нестабильный размер `FBV.exe`: все
  собственные исполняемые модули проверяются одинаково — по наличию, PE/x86,
  версии, metadata и обязательным smoke-тестам. Portable-пакет теперь явно
  проверяется и на наличие `FBV.exe`.

Все заметные изменения локальной ветки модернизации FictionBookEditor фиксируются в этом файле.

### Добавлено

- Пользовательские JavaScript-скрипты получили документированный API
  `window.external` для полного пути, имени файла и каталога открытой книги.
  До первого сохранения методы возвращают пустую строку.

- Во вкладке «Настройки FBE Next» появилась опция показа полного пути к
  открытому файлу в заголовке окна. По умолчанию она выключена; длинные пути
  сокращаются по доступной ширине окна с сохранением имени файла.
- Исправлен runtime JSON для этой опции: при языке «Определяется системой»
  используется перевод системной локали, а не английский fallback.

- FBE Next теперь полностью отделяет пользовательское состояние от старого
  редактора: настройки, словари, аварийные копии, crash-отчёты, startup/update
  trace и опубликованный язык интерфейса хранятся в `%LOCALAPPDATA%\FBE Next`,
  а параметры и MRU — в `HKCU\Software\FBETeam\FictionBook Editor Next`.
  Встроенные плагины получили отдельные COM GUID и собственные ключи Next,
  поэтому одновременная установка старого FictionBook Editor и FBE Next не
  должна перезаписывать их регистрации или настройки друг друга.

- Установщик получил те же 12 языков интерфейса, что и FBE: English, русский,
  українська, Deutsch, français, español, italiano, polski, português,
  Nederlands, čeština и български. В разделе «Языки интерфейса» английский
  пакет обязателен как надёжный fallback, русский и украинский выбраны по
  умолчанию, остальные можно подключить по желанию. Пакеты содержат runtime
  JSON-переводы и локализованный пункт «Проверить FB2 на ошибки» в контекстном
  меню; словари по-прежнему выбираются отдельно. Для девяти новых языков
  стандартные страницы NSIS локализованы штатными таблицами NSIS, а редкие
  продуктовые строки пока безопасно используют английский fallback.

- Для дальнейшей вычитки локализации установщика подготовлен отдельный
  редактируемый каталог его собственных строк. Это упрощает подключение
  переводчиков и будущую работу через Weblate, не меняя поведение уже
  проверенного мастера установки.

- MUI-ресурсы shell-команды «Проверить FB2 на ошибки» перенесены из корня
  приложения в `Lang\Shell`: рядом с FBE.exe больше не лежат host DLL и 12
  языковых каталогов. Проводник продолжает автоматически выбирать подпись по
  языку Windows, а установка, обновление, repair-сценарий и удаление учитывают
  новую раскладку и убирают файлы из прежнего расположения.
